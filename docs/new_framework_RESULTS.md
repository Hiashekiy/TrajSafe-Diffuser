## 1. 训练

| 项 | 值 |
|---|---|
| 控制点 C / 椭圆查询 Q / 解码点 | 32 / 64 / 128 |
| 路径输入 | 单条 `active_path [B,128,2]`（无候选、无 TopologyHead、无 q_coarse） |
| Control Backbone / Final Denoiser | 1 层 / 4 层 TrajBlock |
| 参数量 | 4.05 M |
| 训练 rollout | 4 步：①无路径无安全无反馈 → **PDG-Focal A\*（离线缓存）** → ②路径+64 椭圆无反馈 → ③④路径（ALM 验证后更新）+ 真实反馈 |
| **训练内闭环** | **有**：碰撞 → 局部走廊 cell → 局部约束包 → ALM → 全局验证 → 通过才更新 `active_path` 并产生 `Δ=q0_safe−q0_raw` |
| 优化 | AdamW 2e-4 / wd 1e-4 / batch 16 / grad-clip 1.0 |
| 训练量 | **170 / 200 epoch**（`max_hours=10` 触发停止），~150–200 s/epoch |
| 选模 | `best_task.pt` = **ep 138**（val_loss 0.0217），ep 138 之后 val 变差（过拟合） |

训练曲线（`train_log.jsonl`，当前段的 170 行）：

| epoch | train | val | ctrl MSE | smooth | 碰撞(软) | ALM 通过率 | ALM 修正量 |
|---|---|---|---|---|---|---|---|
| 0 | 0.235 | 0.140 | 0.250 | — | 0.489 | 0.00 | 0.34 scene |
| 30 | 0.023 | 0.030 | 0.0137 | 0.190 | 0.071 | 0.37 | 0.001 |
| 77 | 0.0159 | 0.031 | 0.0122 | 0.165 | 0.096 | 0.43 | 0.0004 |
| 138（best） | 0.0138 | **0.0217** | 0.0106 | 0.160 | 0.058 | 0.39 | 0.0003 |
| 170（停） | 0.0127 | 0.0297 | 0.0128 | 0.156 | 0.088 | 0.33 | 0.0003 |

**结论：ep40 之后指标进入平台并开始过拟合**（val 0.0217 → 0.0297，train 仍在降）。
即 170 epoch 里有效学习集中在前 40 个；这不是"训练充分"，是"时间用尽 + 已过拟合"。

## 2. 测试集（420 个 case，4 步推理，ep138）

| 指标 | 值 |
|---|---|
| PDG-Focal A\* 成功率 / 回退率 | **100% / 0%**（420/420 用的是引导搜索结果，无直线兜底） |
| 搜索路径居中（新增） | clearance 6.1–6.5 → **7.1–7.3 m**，10 ms/条 |
| 扩展节点中位数 / 搜索耗时中位数 | 207 / **93.1 ms** |
| 安全栅格构建 / 单样本总耗时 | 219.6 ms / **3.13 s**（4 步 + 搜索 + 局部走廊 ALM） |
| **最终碰撞率（均值 / 有碰撞样本比例）** | **1.03% / 9.52%（40/420）** ← 旧链路 + 居中 + 插点 |
| 对照：旧链路 + 居中（无插点） | 1.01% / 9.29%（39/420） |
| 对照：旧链路 + 未居中路径 | 2.34% / 17.1%（72/420） |
| 曲线 RMSE（vs GT，scene 单位） | 0.0889（≈7.1 m） |
| 端点误差 | **0.0** |
| 起点 / 终点朝向 cos | **0.976 / 0.975** |
| ALM 执行率（有碰撞才跑） | 59.0% |
| 其中全局验证通过率 | **41.9%** |
| `active_path` 被更新比例 | **24.8%** |
| 搜索路径居中后的 clearance | 6.1–6.5 m → **7.1–7.3 m** |
| 曲线长度中位数 | 95.4 m |

读法：闭环链路在真实数据上确实工作——2/3 的样本需要约束，其中 3/4 的 ALM 修正通过
全局碰撞验证，一半样本的 `active_path` 被真正替换。剩余 6.67% 的碰撞样本是**验证被拒
之后没有换路径**的那些（按 §6.3 不允许用未验证的修正）。

## 3. 消融（同一 ckpt = ep138，同一 test）

除特别说明外都是 420 个样本、4 步推理：

| 配置 | 碰撞率（均值） | 有碰撞样本 | 曲线 RMSE | ALM 验证通过 | 路径更新 | 单样本耗时 |
|---|---|---|---|---|---|---|
| **主配置**：4 步 + 朝向 + 局部走廊 + 反馈 | 1.25% | 6.7%（28/420） | 0.089 | 77.5% | 52.4% | 3129 ms |
| 关掉端点朝向 | **0.66%** | **4.5%（19/420）** | 0.098 | 78% | 54% | 3192 ms |
| 走廊改成全量（不局部） | 1.24% | **9.3%（39/420）** | 0.089 | **58%** | **39%** | 3564 ms |
| 关掉反馈（不喂 Δ） | 1.31% | 7.1%（30/420） | 0.089 | 77% | 52% | 3237 ms |
| 16 步推理（**同一 120 样本子集**） | 0.48% | 2.5% | 0.0387 | 83% | 33% | **976 ms** |
| 4 步推理（**同一 120 样本子集**） | **0.40%** | **1.7%** | 0.0386 | 100% | 33% | **552 ms** |

**结论：**

1. **局部走廊（§5.2/§5.4）确实有用**：同样的模型，局部走廊把 ALM 全局验证通过率从
   58% 提到 77.5%、路径更新率从 39% 提到 52%、碰撞样本从 39 个降到 28 个，而且**更快**
   （3129 vs 3564 ms）——因为只对碰撞区间建 cell/装配约束。
2. **端点朝向是有代价的**：关掉朝向约束后碰撞从 1.25% 降到 0.66%、有碰撞样本 28→19，
   但曲线 RMSE 从 0.089 变差到 0.098。也就是说朝向约束把曲线"掰"向指定切向，
   在窄通道里更容易贴到障碍。是否保留应该由下游（ALM/控制）决定，不能默认说它更好。
3. **反馈分支收益很小**（1.31% → 1.25%），这与"训练早期 `alm_ok=0`、反馈有效样本比例
   只有约 30–45%"一致；它没有被充分训练到能起大作用。
4. **4 步 vs 16 步**（同一 120 样本子集，唯一可比的组合）：4 步的碰撞率 0.40%、RMSE 0.0386、
   552 ms；16 步是 0.48%、0.0387、976 ms。**4 步在质量和速度上都不差于 16 步**
   （速度快 1.8 倍），支持方案里"推理 4 步"的选择。
   注意：这 120 个样本比全量 420 个容易（全量是 1.25% / 0.089），因此**不能**把这一行与
   表首的 420 样本行横向比较。

**关于耗时口径**：表首"主配置 3129 ms"是在 GPU 还被其它进程占用时测的；干净环境下
batch=8 的实测是 **552 ms/样本（4 步）**、976 ms（16 步），见 `outputs/v5_eval_120`。
报告对外只应引用干净口径，并注明 batch=8、单卡 4070。

## 4. 与旧框架对照

| 项 | 旧框架（v4，C=48 + 候选骨架 + 16 步） | 新框架（v5，C=32 + 单路径 + 4 步） |
|---|---|---|
| 训练量 | 200 epoch（T=16 两步 rollout） | 170 epoch（T=16 四步 rollout，含 ALM） |
| 推理步数 | 16 | **4** |
| 搜索 | 无（候选骨架匹配） | **PDG-Focal A\***，100% 成功、93 ms |
| 测试碰撞 | 旧实验记录：3/420（0.7%） | **28/420（6.67%）** |
| 端点/朝向 | 端点精确，无朝向约束 | 端点精确 + 朝向 cos 0.976 |

新框架**没有**超过旧模型的碰撞指标，原因明确：训练量只有 170 epoch 且 ep138 后过拟合、
路径条件是锯齿栅格路径（见下）、且 4 步推理比 16 步少 12 次前向。

## 5.5 最终版：Q=128 + 居中训练路径 + last_verified（2026-11-17）

**设置**：C=32 / Q=128 / 路径 128 点（**训练与推理都用居中后的 A\* 路径**）/ 1 层 backbone /
4 层 final / 4 步闭环 rollout（训练内 ALM，**插点关闭**）/ `lambda_shape 0.20` /
**训练到 ep 73（best = ep65，val 0.04298）**，之后进入平台期主动停止（未跑满 200）。

### (a) 主结果（test 420，4 步推理，居中 + 不插点 + `last_verified` 逐样本选择）

| 指标 | Q=64（ep138） | **Q=128（ep65）** |
|---|---|---|
| **有碰撞样本** | 2 / 420（0.48%） | **2 / 420（0.48%）** |
| 碰撞率均值 | 0.08% | 0.15% |
| 曲线 RMSE | **0.0871** | 0.0985 |
| 端点误差 | 0.0 | 0.0 |
| 起点/终点朝向 cos | **0.971 / 0.971** | 0.969 / 0.969 |
| PDG-Focal A\* 成功率 / 回退率 | 100% / 0% | 100% / 0% |
| 扩展中位数 / 搜索耗时 | 207 / 60 ms | 210 / 55 ms |
| **ALM 执行率 → 通过率** | 59.0% → **34.7%** | 74.3% → **87.2%** |
| `active_path` 更新率 | 21% | **65%** |
| 单样本耗时 | 2563 ms | **2176 ms** |
| 输出来源 `model / last_verified / search_path` | — / 31 / 6 | **400 / 18 / 2** |

**读法**：两者碰撞都压到 **2/420**，说明"输出安全"主要来自**居中路径 + last_verified**
这套机制，而不是 Q 的密度；Q=128 换来的是 **ALM 通过率 35%→87%、路径更新 21%→65%**，
但 **RMSE 反而差一点（0.0985 vs 0.0871）**——Q=64 那个模型多训了一倍 epoch（138 vs 65），
精度上占优；两者训练量不同，不能直接说 Q=128 更差。

### (b) 消融（Q=128，ep65，test 420；最后一行用同一 120 样本子集）

| 配置 | 碰撞率均值 | 有碰撞样本 | RMSE | 朝向 cos | ALM 通过 | 路径更新 |
|---|---|---|---|---|---|---|
| **主配置**（4 步 + 朝向 + 反馈） | 0.15% | 2/420 | 0.0985 | 0.969 | 87% | 65% |
| 关掉端点朝向 | 0.15% | 2/420 | **0.1091（更差）** | 0.650 | 92% | 67% |
| 关掉反馈 | 0.15% | 2/420 | 0.0991 | — | 87% | 65% |
| 4 步（120 子集） | **0.00%** | 0/120 | **0.0439** | — | **100%** | 47% |
| 16 步（同一 120 子集） | 0.00% | 0/120 | 0.0518（更差） | — | 88% | 47% |

**结论**：
1. **端点朝向是真约束**：关掉后 RMSE 0.0985 → 0.1091、朝向 cos 0.969 → 0.650；
2. **反馈分支仍无贡献**（0.0985 vs 0.0991），与"训练时 ALM 有效性只有 60%、反馈多为 invalid"一致；
3. **4 步不输 16 步**（同一 120 样本：0.0439 vs 0.0518），验证了方案里"推理 4 步"的选择；
4. 碰撞在 420 个里只剩 2 个，且都是"全程没有可验证曲线 + 模型自己仍碰撞"的极端样本
   （输出退到居中搜索路径，`search_path` = 2）。

|---|---|---|---|---|
| 45 | 0.86 | 0.60 | 0.005 scene | 0.0012 |

## 6. 已知限制（必读）

1. **训练量不足且已过拟合**：170/200 epoch，ep138 之后 val 变差；有效学习集中在前 40 epoch。
2. **路径条件是锯齿栅格路径**：`pdg_path_points` 是 PDG-Focal A\* 的原始栅格折线按弧长重采样，
   未平滑（方案 §3.2 只要求重采样）。它是训练/推理一致的，但比 GT 平滑曲线更难拟合，
   这解释了 ctrl 精度（0.0106 ≈ 1 m）比"用 GT 曲线当路径"的阶段（0.0021 ≈ 0.16 m）差 5 倍。
3. **地图**：k4p 的障碍已被腐蚀 4 格（不是安全膨胀），搜索在它上面再膨胀 r=0.8+0.3 m；
   净效果比真实障碍薄约 2.2 格，**不能声称安全边界精确**。
4. **朝向是代理标签**：GT 曲线端点切线，不是车辆 yaw。
5. **ALM 只覆盖碰撞区间**：通过几何门槛后无碰撞的样本不建走廊、不更新路径（§6.1），
   因此"路径更新率 52.4%"不是失败率。
6. 单样本 3.13 s 里 220 ms 是安全栅格构建、93 ms 搜索、其余是 4 次网络前向 + ALM；
   比旧框架的 16 步更快，但**尚未与旧框架在同一测试上逐样本对齐**（旧框架的 420 个结果
   来自历史实验记录，数据根不同：C=48 根 vs 新的 C=32 根）。
