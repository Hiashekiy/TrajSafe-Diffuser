## 0. 结论摘要

主实验：**现有训练好的模型**（`outputs/models/oneshot_k4p_c48/ckpt/best_task.pt`，
`C=48`，160 m/256 px）在 **test 划分 200 个真实 case** 上，用**逆扩散第 3 步的中间干净
状态 x0** 作为软引导参考（`guidance="none"`，纯 DDIM，无走廊/无 ALM），
`cell = 0.625 m`，`w = 1.2`，`J = 3`。

| 方法 | 扩展中位数 | 搜索循环 ms 中位数 | 端到端 ms 中位数 | 代价/最优 中位数 |
|---|---|---|---|---|
| Dijkstra | 5720 | 133.5 | 180.6 | 1.000 |
| A*（octile） | 585 | 19.4 | 63.7 | 1.000 |
| Focal A*（clearance 次级） | 1185 | 44.2 | 94.7 | 1.000 |
| Focal A*（index 次级） | 4667 | 150.6 | 201.9 | 1.000 |
| **Ours（PDG-Focal A\*）** | **179** | **11.8** | **56.9** | **1.032** |

* **节点扩展数：** 比 A* 少 **3.3×**，比普通 Focal A*（clearance）少 **6.6×**，
  比 Dijkstra 少 **32×**；搜索循环时间比 A* 少 **1.6×**。
* **路径代价：** 中位数 +3.2%（均值 +4.8%，最大正好 1.200 = w 上界），
  与所实现 Focal Search 变体的 `w` 有界次优一致；路径 100% 通过独立复核。
* **成功率：** 200/200 成功；**参考轨迹在 16.5% 的 case 上穿障**（平均穿障比例 2.9%），
  搜索仍然全部返回合法路径 —— 软引导 + 全图兜底按设计工作。
* **端到端口径要说清楚：** A* 不需要引导场，它的端到端是 41.7 ms；PDG 的端到端
  56.9 ms 里有 23.7 ms 是**每次查询重建引导场**。所以单次查询 PDG 比 A* 慢
  ~15 ms（+36%），**节点节省并不自动等于墙钟加速**。这是本报告最重要的诚实结论。
* **进度项（|u_j − u_g|）在本数据上没有带来收益：** 消融 G1（仅距离）177.5 →
  G2（距离+进度）179.5 扩展，`alpha_p ∈ {0, 0.5, 1, 2}` 扫描平坦（168–187）。
  距离项贡献了几乎全部收益；进度项的作用只在个别自交/回头参考上可验证（见 §5.6）。
* **K 的影响很小：** K=1 的 x0（最噪）已经能给出 176.5 扩展，K=3 为 173.5 —— 意味
  可以只跑 1–3 步反扩散就拿引导，而不必跑满 16 步。

## 1. 实现概要（对应设计 §12）

| 模块 | 职责 |
|---|---|
| `grid_map.py` | 占据值语义（0=free/1=obstacle，unknown 视为障碍）、`GridSpec` 坐标映射、欧氏障碍膨胀、安全栅格、clearance 场 |
| `grid_neighbors.py` | 8 邻域表（`idx[N,8]`、对角线 = √2·cell）、**禁止穿角**（两个侧邻格都必须是自由格） |
| `diffusion_path.py` | x0 → 栅格坐标、端点校正、越界/NaN/退化检测、去重、弧长重采样、共线合并 |
| `progress_guidance.py` | 每格最近 `J=3` 个**线段精确投影**候选 `(d_j, u_j)`；`H_D(x,g)` 在节点入 FOCAL 时用当前 `g` 计算 |
| `focal_astar.py` | anchor A*（octile）+ 动态 FOCAL + 次级排序 + reopen + 独立复核前的真实代价 |
| `baselines.py` | Dijkstra / A* / Focal A*（clearance、index 两种固定次级）/ PDG |
| `path_validation.py` | 独立复核：越界、障碍、边合法性、穿角、代价复算、转弯数、最小间隙 |
| `visualization.py` | 设计 §9 要求的 8 类真实数据图 |
| `scenes.py` | T1–T12 合成验收场景 |
| `benchmark.py` | case 准备、共享输入的批量评估、聚合、CSV |
| `tests/` | 49 个 pytest（T1–T12、Focal 正确性、引导场、独立复核） |

### 1.1 实现的是哪个 Focal Search 变体（设计 §11）

* anchor 是 8 邻域 A*，`h0` = octile distance（可采纳且一致）。
* `FOCAL = {v ∈ OPEN : f0(v) ≤ w·f_min}`，`f_min` 是**当前** OPEN 的活最小值；
  **每一轮重建**，不是开局算一次。
* 选中节点在 FOCAL 内按 `(H_D, f0, −clearance, index)` 排序（设计 §5.3 的平局次序）。
  Diffusion **不进入** `g`、边代价或 FOCAL 阈值。
* CLOSED 节点若拿到更小 `g` 会 reopen（并计数）；目标只有在**从 FOCAL 中被选中扩展**
  时才返回。
* 因此可声明的保证：`h0` 可采纳 + 上述更新/终止规则 ⇒ 返回路径代价 ≤ `w·C*`。
  **实测验证**：`w=1.0` 时与 Dijkstra 代价逐位相同；`w∈{1.1,1.2,1.3,1.5}` 时
  200/80 个 case 的代价比最大正好 1.200（见 §5.1、§5.4）。
* 不声明：`H_D` 的任何最优性/单调性；参考轨迹的可行性；栅格路径的平滑性。

### 1.2 实现中发现的、影响数字口径的一个细节

FOCAL 允许在 `w·f_min` 范围内选节点，因此**目标节点可能比另一个 f0 更小的 FOCAL 成员先被
扩展**。此时按父指针重建出的路径有可能比 `g(goal)` 更便宜（实测 4/200 个 case 差 1.25 m）。
本实现因此：

* `path_cost_m` = **重建路径的真实边权之和**（与独立复核逐位一致）；
* `search_cost_m` = `g(goal)`，即 Focal 界对应的量，单独记录。

若不这样处理，`path_valid` 会因为“代价对不上”而误报 2% 失败（第一版就踩到了，已修正）。

## 2. 实验设置

| 项 | 值 |
|---|---|
| 数据 | `data/processed/160m-k4p-c48/test`（420 样本，256×256，160 m 场景） |

| Diffusion | 现有 ckpt，纯 DDIM（`guidance="none"`），16 步全长反向；参考 = 第 K 步的 `x0` 曲线（128 点） |
| K（主实验） | 3（t=13），另做 K∈{1,2,3,4,5} 扫描 |
| `J` / `sigma_d` / `alpha_d` | 3 / `3·cell = 1.875 m` / 1.0 |
| `alpha_p` | 1.0（扫描 0/0.5/1/2） |
| `w` | 1.2（扫描 1.0/1.1/1.2/1.3/1.5） |

| 重采样 | 2 格步长 + 共线（<5°）合并；只做端点校正，不整体缩放 |

| 计时 | `perf_counter`，GPU 侧 `cuda.synchronize`；搜索/引导/预处理/复核分开计 |

端到端口径：`T_total = T_warmup(K 步反向，按 16 步摊销) + T_preprocess + T_reference +
T_guidance + T_search + T_validation`，各项独立测量，不重复计时。

## 3. 主对比（200 case）

`outputs/grid_search/run_pdg/REPORT_TABLES.md`）

| 配置 | 扩展中位数 | 扩展均值 | 扩展 P95 | 搜索 ms 中位数 | 搜索 ms P95 | 端到端 ms | 端到端(不含引导) ms | 代价中位数 m | 代价/最优 中位数 |
|---|---|---|---|---|---|---|---|---|---|
| Dijkstra | 5720.5 | 6374 | 12187 | 133.52 | 277.5 | 180.6 | 155.9 | 90.21 | 1.000 |
| A* | 585.5 | 1336 | 5515 | 19.37 | 171.9 | 63.7 | 41.7 | 90.21 | 1.000 |
| Focal A*(clearance) | 1185.0 | 2219 | 5732 | 44.20 | 206.1 | 94.7 | 66.9 | 91.14 | 1.000 |

成功率 200/200，独立复核通过率 200/200（全部方法）。

参考轨迹统计（同一批 200 case）：有效率 100%，长度中位数 95.4 m，
**平均穿障比例 2.9%，16.5% 的 case 至少有一段落在障碍上**；
引导场对**全图 100% 的栅格**都有候选（`coverage = 1.000`，其中 1.5% 的格子在 3 格以内）；

要额外付 23.7 ms 的引导场构建，所以对“一次地图一次查询”的场景 PDG 反而更慢。
只有当引导场能复用（同一张图/同一段参考被多次查询，或把构建放进离线阶段）时，
端到端才会真正优于 A*。

## 4. 进度项消融 G0 / G1 / G2（200 case，同一 anchor、同一 w=1.2）

| 配置 | 距离项 | 进度项 | 扩展中位数 | 搜索 ms 中位数 | 代价中位数 m |
|---|---|---|---|---|---|
| G0（= Focal A* clearance） | 无 | 无 | 1185.0 | 43.59 | 91.14 |
| G1 | 有 | 无 | **177.5** | 11.13 | 94.15 |
| G2（Ours） | 有 | 有 | 179.5 | 11.04 | 94.15 |

结论：**距离项贡献 6.7× 的扩展削减；进度项在本数据上略微变差（+1.1%）**。
`alpha_p` 扫描（80 case）同样平坦：0→170.5，0.5→168.0，1.0→173.5，2.0→187.0，
代价完全不变（92.85 m）。

这是负面结果，按设计要求如实报告：在“参考轨迹是平滑 B 样条、极少自交”的真实数据上，
`|u_j − u_g|` 提供的额外信息被距离项覆盖；进展信息只有在参考轨迹出现**自交、回头、
平行近邻**时才有判别力（§5.6 的合成场景，以及单元测试
`test_t5_crossing_cell_keeps_distinct_progress_candidates` /
`test_t6_parallel_legs_are_disambiguated_by_progress`）。

## 5. 参数实验（单因素，80 case）

### 5.1 K（用第几步的中间 x0）

| K | Ours 扩展中位数 | 仅距离 扩展中位数 | A* 扩展中位数 | Ours 代价中位数 | 参考穿障比例均值 | 存在穿障的 case |
|---|---|---|---|---|---|---|
| 1 | 176.5 | 163.0 | 670 | 93.04 | 1.01% | 11.3% |
| 2 | 174.5 | 159.5 | 670 | 92.85 | 0.97% | 11.3% |
| 3 | 173.5 | 170.5 | 670 | 92.85 | 0.91% | 11.3% |
| 4 | 182.0 | 169.0 | 670 | 92.18 | 0.81% | 11.3% |
| 5 | 183.0 | 166.0 | 670 | 92.07 | 0.73% | 8.7% |

* 逆扩散早期的 x0（K=1）已经足够引导，扩展数几乎不随 K 变化 ⇒ 引导阶段可以只用
  1–3 步反扩散，省掉后续步数的开销（对上游管线是实打实的收益）。
* 参考穿障比例随 K 略降（1.01% → 0.73%），但**搜索从未因此失败**（成功率 100%）。

### 5.2 w（Focal 权重）

| w | Ours 扩展中位数 | Ours 代价中位数 m | 代价/最优 | Focal A*(clearance) 扩展中位数 |
|---|---|---|---|---|
| 1.0 | 443.0 | 87.70 | 1.000 | 637.5 |
| 1.1 | 251.5 | 90.06 | 1.027 | 1012.0 |
| 1.2 | 173.5 | 92.85 | 1.059 | 1185.0 |
| 1.3 | 166.0 | 93.44 | 1.065 | 1272.5 |
| 1.5 | 157.5 | 93.99 | 1.072 | 1576.0 |

* `w=1.0`（代价严格最优）时仍是 A* 的 **1.51×** 更少扩展（443 vs 670）—— 说明引导在
  “最保守”的设置下也能靠 FOCAL 内的排序省节点。
* `w` 增大时 PDG 与固定次级 Focal 基线的扩展数**反向变化**：PDG 的 FOCAL 越大，
  引导越能在大候选集里挑到好节点；固定次级（clearance）越大越乱。这正是“引导必须
  放在 FOCAL 内”的意义。

### 5.3 alpha_p

见 §4 的扫描：0.0/0.5/1.0/2.0 → 170.5/168.0/173.5/187.0，单调性都没有，`2.0` 明显变差。

## 7.5 高难度场景套件（新增，回应"CARLA 测试集太简单"）

### 7.5.1 为什么原测试集偏简单

CARLA 的 160 m 窗口是一张道路网：可行驶区是若干条 2.5–4 m 宽、基本不通航的走廊，
网格搜索近似 1 维，A* 只扩 100–600 个格。按 A* 扩展数把 200 个 case 分位数切开：

| 难度分层 | n | A* 扩展中位数 | Focal A* | Ours | 扩展削减 | 代价增量 | 参考穿障率 |
|---|---|---|---|---|---|---|---|
| 简单 25% | 50 | 114 | 594 | 132 | **0.86×（更差）** | +7.9% | 0.0% |
| 中间 50% | 100 | 586 | 1185 | 176 | 3.32× | +5.9% | 0.3% |
| 困难 25% | 50 | 3284 | 3810 | 1875 | 1.75× | +1.6% | 11.0% |
| 最难 10 | 10 | 6638 | 6434 | 5137 | 1.29× | +0.8% | 16.4% |

即：**原数据集在简单半数上根本不需要引导**，引导只在"有真实分支/绕行"的 case 上
才省节点。因此补一套专门的困难场景。

### 7.5.2 困难场景（`src/grid_search/hard_scenes.py`）

| H2 maze_b | 近完美迷宫（26×26，10% 拆墙） | 105×105 | 0.75 | 5901 |

| H1 maze_a | 3033 | 900 | **3.37×** | 9430（0.32×，被带偏） |
| H2 maze_b | 5901 | 9154 | 0.64×（更差） | 8884 |
| H3 rooms | 1508 | 95 | **15.9×** | 855（1.76×） |
| H4 spiral | 751 | 650 | 1.16× | 600（1.25×） |
| H5 comb | 207 | 166 | 1.25× | 248（0.83×） |
| H6 long_wall | 3737 | 3046 | 1.23× | 2991（1.25×） |

**关键（负）发现：** H2（近完美迷宫）里即使参考是**最优路径**，Ours 的扩展也是 A* 的
1.56 倍。原因是引导的距离项用的是**欧氏距离**——隔着一道墙的格子到参考"很近"，
但沿可行驶空间其实很远，FOCAL 就把搜索拉进墙后的死角。这解释了为什么 maze 场景
收益不一致，也指出下一步的正确改法：距离项改用**自由空间上的测地距离**
（多源 BFS / 稀疏图 Dijkstra，参考轨迹栅格化后一次最短路），设计 §4.1 允许这种
"栅格化加速 + 精确校验"的写法。这不是调参问题，是距离度量的问题。

可视化：`outputs/grid_search/run_hard/fig_hard_paths.png`（6 场景三方法路径）与
`fig_hard_stats.png`（按参考质量分组的扩展数/代价柱状图）。
复现：`python scripts/grid_search/run_hard_suite.py --out outputs/grid_search/run_hard`。

## 7.6 对照实验：把引导项融进 A\* 代价（已评估，**不采用**）

按需求实现了"引导代价 + 权重"的融合版（`baselines.guided_astar(safe, s, g, field, lam=...)`）：

```
g(v) = 真实移动距离 + lam · Σ min_j [ d_j + alpha_p · L_ref · |u_j − u_g| ]
f(v) = g(v) + octile(v)
```

`lam = 0` 与 A\* 逐位一致（有单测）。扫描 `lam ∈ {0.02,0.05,0.1,0.2,0.5,1.0}` ×
`alpha_p ∈ {0,1}`（100 个 CARLA case / 24 个难 case，`w=1, secondary=index`）：

| 配置（CARLA 100 case） | 扩展中位数 | 代价/最优（中位） | 付出惩罚 |
|---|---|---|---|
| A\* | 355 | 1.000 | 0 |
| **FOCAL 排序版（Ours，现用）** | **171** | **+3.4%** | 0 |
| 融合 λ=0.02，α_p=0 | 954 | +0.7% | 1.1 m |
| 融合 λ=0.2，α_p=0 | 1380 | +2.8% | 4.8 m |
| 融合 λ=1.0，α_p=0 | 1538 | +3.6% | 22.0 m |
| 融合 λ=0.02，α_p=1 | 2116 | +0.7% | 4.7 m |
| 融合 λ=1.0，α_p=1 | 3131 | +4.3% | 128.4 m |

| 配置（难场景 24 case） | 扩展中位数 | 代价/最优（均值） |
|---|---|---|
| A\* | 2270 | 1.000 |
| **FOCAL 排序版（Ours）** | **1384** | +1.4% |
| 融合 λ=1.0，α_p=0 | 1644 | +9.0% |
| 融合 λ=0.02，α_p=0 | 1908 | +1.3% |
| 融合 λ=0.02，α_p=1 | 2696 | +0.8% |

**为什么融合版反而更慢**（三条机理，实测可分离）：

1. **启发式失效**：真实剩余代价 = 剩余路程 + 剩余惩罚，而 `h` 只估前者。惩罚占比越大，
   `h` 的相对信息量越小，大量节点的 `f` 挤在一起 → 无法剪枝 → 退化为 Dijkstra
   （CARLA：A\* 355 → λ=0.02 就 954，λ=1.0 到 1538）。
2. **惩罚量级失控**：λ=1.0 时全程惩罚 22 m（CARLA）/ 594 m（难场景，路径本身仅 160 m），
   目标函数已经不是"最短路径"。
3. **进度项让代价依赖已走距离**：α_p=1 时同一格的惩罚随当前 `g` 变化 → 代价不再是格的
   静态属性 → "每格最多展开一次"的前提被破坏 → 大量 reopen。同 λ=0.02 下
   α_p=0 是 954 格，α_p=1 是 2116 格（2.2 倍）。

**结论**：融合版是双输（格子更多、真实路径更长），只作为 §7.6 的对照保留在
`baselines.guided_astar` 里，默认不使用。若将来仍想保留"融进代价"的写法，可尝试：
给 `h` 补一项剩余惩罚下界、用加权 A\*（h×1.5~2）补偿锐度、或把惩罚截断成
"出走廊才罚"。这三条都未实测，不写进结论。

图：`outputs/grid_search/run_fused/fig_fused_tradeoff.png`（左 CARLA、右难场景）。
复现：`python scripts/grid_search/run_fused_guidance.py --cache <x0.npz> --limit 100
--out outputs/grid_search/run_fused`。

## 9. 已知问题与后续

1. **引导场构建 23.7 ms/查询** 是端到端的主要开销（已从 52.9 ms 优化到 23.7 ms：
   精确投影改为 float32 + 分块 + 单次 argpartition）。进一步可用设计 §4.1 允许的
   “栅格化折线 + 距离变换 + 精确线段校验”混合方案，把远场近似掉。
2. **栅格路径锯齿**：`turn_count` 中位数 25（A* 4.7）。这是 8 邻域下沿着参考轨迹
   在对角/直行之间交替的结果，代价只多 3–6%；平滑本来属于下游安全走廊/Bézier，
   本任务范围外（设计要求不得改动）。
3. **进度项无收益**（§4）。可选改法：`L_ref` 改用 `max(L_D, L_anchor)`（设计 §4.2 提到
   的替代尺度）、加设计 §4.4 的方向回退惩罚、或直接把 `alpha_p` 置 0（G1）。
4. **FOCAL 维护是 O(OPEN)**：本轮已把 Python 堆换成“紧凑 OPEN 数组 + 向量化扫描”，
   在 256×256 图上足够（搜索 11.8 ms 中位数），但更大图上应换成按 f0 分桶的增量结构。
5. **`focal_index` 基线异常慢**（4667 扩展 / 150 ms）：它说明“FOCAL 内的次级排序规则
   极其重要”，同时也说明任何次级规则都必须有几何含义，否则等于随机搜索。
6. 本轮只在 test 的 200/420 个 case 上做统计；train/val 未做（避免与训练分布混淆），
   跨场景泛化不在本任务范围。
