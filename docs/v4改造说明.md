# v4 改造说明（单 16×16 地图特征 / 修正量反馈 / 统一连续安全损失）

分支：`v4-map16-fbdelta-safeloss`（从 `v3-skeleton-dynamic` 的 74d6140 拉出）
数据：`data/processed/160m-k4p-c48`（C = 48 控制点，160 m / 256 px 窗口）
配置：`configs/config_160k4p_c48_v4_map16.yaml`
入口：`scripts/v4_train_c48.sh`（bash）/ `scripts/v4_train_c48.cmd`（双击）
输出：`outputs/models/v4_map16_c48/`（`ckpt/` + `train.log`）

---

## 1. 地图特征：只保留一份 16×16

**改动前**：`SceneCNN` 输出两份地图特征
- `C_G`：16×16 全局记忆（控制主干 / FinalDenoiser）；
- `C_E`：32×32 精细几何记忆（`geo_decode_res: 64 → geo_mem_res: 32`，
  由 `_UpFuse` 上采样 + 编码器 skip 融合得到），供椭圆几何交叉注意力使用。

**改动后**：只有一份 16×16 的 `C_G`，两份模块读同一个张量。

| 文件 | 变化 |
|---|---|
| `src/models/common/scene_cnn.py` | 删除 `_UpFuse`、`geo_decode_res` / `geo_mem_res`、`enc_ch` 与精细解码器；`forward(occ) -> [B,d,16,16]` |
| `src/models/trajsafe/planner.py` | `scene_tokens()` 返回单个 `C_G`；`EllipseGeometry(map_res=global_res, ...)`；移除 `geo_mem_res` / `geo_decode_res` 配置读取 |
| `src/models/trajsafe/ellipse.py` | 参数 `geo_mem_res` → `map_res`（=16），在 `C_G` 上做带空间偏置的交叉注意力 |
| `configs/*.yaml` | 删除 `model.geo_decode_res` / `model.geo_mem_res` |

注意力规模因此从 1024 个 key/value token 降到 256。椭圆的中心距离偏置公式不变，
只是栅格中心网格从 32×32 换成 16×16。

## 2. 修正反馈：只回传「修正量 + 有效标签」

**改动前**：每个控制点的反馈输入是 5 维 `[x_safe, y_safe, dx, dy, valid]`，
其中 `(x_safe, y_safe) = Q0_safe_prev` 是上一轮 ALM 修正后的**干净轨迹**本身。

**改动后**：3 维 `[dx, dy, valid]`，其中 `dx,dy = Q0_safe_prev − Q0_raw_prev`
（上一轮 ALM 实际施加的修正量），`valid` 是该输出是否通过冻结约束包。
`Q0_safe_prev` 不再进入网络——否则下一步反向去噪会退化成“抄 ALM 输出”。

| 文件 | 变化 |
|---|---|
| `src/models/trajsafe/feedback.py` | `FEEDBACK_INPUT_DIM: 5 → 3`，`FeedbackEncoder` 输入 `[dx,dy,valid]` |
| `src/models/trajsafe/planner.py` | `feedback_features(h_ctrl, feedback_delta, feedback_valid)`；`forward_all / forward_controls / forward_curve_tokens` 删除 `feedback_control` 形参 |
| `train.py` | `feedback_rollout()` 不再构造 `fb_control`，第二步前向只接收 `(fb_delta, fb_valid)` |
| `src/diffusion/sampler.py` | `feedback_step()` 的返回从 `(control, delta, valid, stats)` 变为 `(delta, valid, stats)`；采样器状态里不再保存 `fb_control`；trace/result 删除 `feedback_control` 字段 |
| `tests/*` | 相应更新（并新增“修正后轨迹不能作为前向输入”的结构断言） |

训练期与推理期的语义完全一致：`valid = 0` 时门控残差严格为恒等（warm-up 与原
扩散模型逐位相同），`valid = 1` 且原本就安全时回传 `delta = 0`。

## 3. 安全损失：统一为连续安全损失 `L_safe`

**改动前**训练里有三个安全项：
1. `ellipse_safety_loss`（原 `L_safe`）：椭圆软栅格 `1 − 自由面积占比` 的均值 + CVaR；
2. `alm_corridor_loss`（原 `L_alm`）：**解码后 128 点曲线**对走廊半空间的穿透量；
3. `feedback_safety_loss`（原 `L_fbsafe`）：第二步原始预测的 Bezier 凸包违反量。

**改动后**只保留第 3 类，改名为 `continuous_safety_loss`，并在**两个阶段**使用同一
定义、同一权重 `lambda_safe`：

```
第 l 段的精确三次 Bézier 控制点   beta_{l,r} = E_{l,r} Q
L_safe = mean_b  max_{l,r,f} relu( A_{l,f} · beta_{l,r} − b_{l,f} )
```

由 `beta_{l,0..3} ∈ R_l ⇒ C(u) ∈ R_l  ∀u ∈ [u_l, u_{l+1}]`（凸包性质），这是对整条
B 样条曲线的连续证书，而不是 128 点采样启发式；它用的 `BSplineConstraintPack` 与推理
期 `bspline_alm_correct()` 投影的是同一个对象。

| 阶段 | 监督对象 |
|---|---|
| 第一阶段（第一次前向） | `out["control"]`（干净控制多边形） |
| 第二阶段（反馈 rollout 第二次前向） | `out2["control"]` |

| 文件 | 变化 |
|---|---|
| `src/losses/losses.py` | 删除 `ellipse_safety_loss` / `alm_corridor_loss`；`feedback_safety_loss` → `continuous_safety_loss` |
| `src/losses/__init__.py` | 导出表同步 |
| `train.py` | 新增 `build_training_pack()`（两阶段共用同一个 pack）；`LOSS_KEYS` 去掉 `Lalm` / `Lfbsafe`；`lambda_alm` / `lambda_feedback_safe` 权重键删除；统计量 `safe_mean/safe_cvar` → `safe_violation` |
| `configs/*.yaml` | 删除 `lambda_alm` / `lambda_feedback_safe` |

`lambda_safe` 是唯一的安全权重，`lambda_safe: 0`（D-C48 等无安全特征的模型）会把该项
整体跳过；`model.safety_features.enabled: false` 时同样跳过（保持 D-C48 的定义不变）。

## 未改动（刻意保留）

- 轨迹表示、拓扑候选、骨架/椭圆查询数量、`num_controls`、扩散调度、ALM 推理链路；
- `Lctrl / Lcoarse / Lsmooth / Lboundary / Ltopo / Lshape / Liou` 的公式与权重；
- `L_curve`（第二步解码曲线的二阶/三阶差分）：它是平滑项而非安全项，保留。
