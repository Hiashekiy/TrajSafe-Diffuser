# V2 — Skeleton-Topology-Grounded Trajectory Diffusion

> V1（Joint P/E Diffusion，`configs/config_v1*.yaml` + `src/models/joint/*`）保持冻结，
> 本文件描述的是**新增**的 V2 主链路。V1 的源码一行未改。

---

## 1. 一句话定义

```
x_T -> ... -> x_tc -> P_hat^c -> m -> s_i -> E_i -> x_tc -> ... -> x_0
```

只保留**一套** trajectory diffusion。传统几何只负责生产「合法候选空间」，
粗轨迹负责在其中选 topology，Progress Head 决定椭圆沿该 topology 怎么分布，
固定中心的 Ellipse Shape Head 学二维安全域，这些椭圆再反过来 condition
**同一条** trajectory diffusion 的后半程。

| 量 | V2 的唯一合法定义 |
| --- | --- |
| diffusion state | 只有 `p`（轨迹），**没有** `e` |
| ellipse centre | `c_i = gamma_m(s_i)`（几何映射，不是网络输出） |
| ellipse shape | `shape4 = [log a, log b, cos 2theta, sin 2theta]`，且 `a >= b` |
| topology | 对若干**已经完整、连通、安全**的候选路径打分后 categorical 采样；绝不预测 branch sequence，绝不 soft-average 坐标 |

## 2. 与 V1 的差异

保留：`SceneCNN`、global scene memory、fine geometry memory、position encoding、
timestep encoding、cosine schedule（T=16）、x0 prediction、DDIM 轨迹更新、
起终点硬约束、轨迹平滑损失、整套 occupancy 椭圆安全损失思想。

删除（V2 代码路径中不再存在，并有 grep 级测试守着）：

* `e_t ~ Gaussian`、`mlp_e(e_t)`、`head_e -> [B,H,6]`
* center offset `Delta c`，即 `c_i = p_i + Delta c_i`
* `x0_e_center_safe`、`ellipse_center_safety_loss`、center SDF loss
* P/E 两条 DDIM 状态并行更新
* ALM 中为了维持 `c = p + delta` 而更新 `delta_c` 的逻辑
* `loss.lambda_center_safe` 配置项

## 4. 八条禁止（`tests/test_v2_contracts.py` 会检查）

1. 禁止继续 diffusing E —— V2 的 diffusion state 只有 trajectory。
2. 禁止 `c_i = p_i + Delta c_i` —— 唯一公式 `c_i = gamma_m(s_i)`。
3. 禁止预测 branch sequence —— 只对完整、连通、安全的候选路径打分。
4. 禁止 soft-average 候选坐标 —— softmax 只产生概率，几何必须落到真实候选上。
5. 禁止每个 timestep 重选 topology —— 只 commit 一次。
6. 禁止用 noisy `p_t` 做 topology matching —— 用当前 `x0_p`（`x0_p_base`）。
7. 禁止复用旧 ellipse center/shape GT —— center 语义已变，shape 必须 fixed-center 重建。
8. 禁止 topology loss 拖 trajectory backbone —— 第一阶段 selector 输入 `detach()`。

## 5. 关键实现细节

### 5.1 骨架与图（no corner cutting）

```
F        = 1 - M                     # 不使用 SDF
M_safe   = Dilate(M, r_c)            # skeleton.safety_dilation_cells = 1
skeleton = GuoHall(1 - M_safe)
```

对角邻接只有在两个正交侧格都 free 时才允许，否则

```
# .
. #
```

这种对角骨架像素会被错误连通，线段会擦过障碍角。该规则在 `skeleton_graph.py`
的 `allowed_neighbour_masks` / `pixel_degrees` / `_neighbours_of` 中统一实现；
`supercover_pixels`（Amanatides-Woo + supercover 拐角处理）用于 start/goal
connector，保证返回的 cell 链一定 4-连通。

graph compression：`deg != 2` 的像素 8-邻接聚成一个 node（同样遵守 no-corner-cut），
node 之间的 degree-2 链压缩成一个 branch，branch 内保留完整 pixel polyline。
纯环（所有像素 `deg==2`）注入 2 个 auxiliary node 变成双 branch 环；
自环 branch（同一 node 内的退化 ladder 伪影）直接丢弃。

两套 mask 是有意为之：

* `free`（未膨胀）—— 碰撞判定、connector、no-corner-cut 规则都用它，紧贴墙的起终点依然可达；
* 膨胀后的 mask 只用于**细化骨架**，从而保证骨架（以及所有 `c_i`）与墙保持 margin。
  这就是 `CenterFree == 1.0000` 的结构性来源。

### 5.2 候选 topology

* Yen K-shortest（networkx `shortest_simple_paths`）在压缩图上跑 `raw_k=16`；
* 长度过滤 `L_m <= 1.5 L_min`；
* branch 集合 Jaccard `> 0.75` 视为同一 topology；
* 最多 `M=4` 个 slot，无效 slot `logits = -inf`，softmax 后概率恰好为 0；
* 弧长重采样到 `L=128`，特征 `[x, y, tx, ty, u]`。

**预处理与推理共用 `generate_candidates()`**，只有一份实现。

### 5.3 标签

* topology：`q_m = softmax(-nDTW(gt, P_m) / tau_gt)`（soft，非 one-hot）；
* progress：GT waypoint 投影到 `m*` 上的弧长参数，做 isotonic 单调投影并钉住
  `s_0=0, s_{K-1}=1`；
* shape：`fixed_center_iris` 对每个 skeleton 像素求解
  `max_P log det P  s.t.  ||P A_j|| + A_j^T c_i <= b_j`（**c_i 是常数**），
  再用 occupancy 采样校验，必要时收缩，保证标签本身绝不碰撞。
  连续 center 用**最近 skeleton 像素**的标签做监督（`SkeletonDataset.shape_at`）。

### 5.4 Loss

```
L = L_P + 0.1 L_smooth + 1.0 L_topo + 0.5 L_prog
      + 1.0 L_shape + 0.25 L_iou + 0.1 L_safe
```

`L_smooth` 与 V1 `train.py:trajectory_smoothness_loss` 数值上完全一致（有测试逐位比对）。
`ellipse_mask_losses(center, shape4, ...)` 的签名已按规格修改，内部不再出现
`center = p_pred + e_pred[..., :2]`。`L_safe` 继续用整椭圆的 occupancy 覆盖率 + 逐轨迹 CVaR。

训练用 teacher forcing：selector 学 soft target `q`，progress / shape /
refinement 一律使用 `m* = argmin_m nDTW`。第一版**不做** scheduled sampling。

### 5.5 Sampler

```
p = torch.randn(B, H, 2)          # 没有 e
15 ... 8     trajectory only
first t <= commit_t (=7)          # 不是 t == commit_t！
                score_candidates -> m ~ Cat(pi) 或 argmax
                COMMIT（此后永不变）
7 ... 0      refine_with_path: s_i^t 每步重算 -> c_i = gamma_m(s_i)
                              -> shape4 -> ellipse token -> 同一个 diffusion 精修
p <- DDIM(p, x0_p)                # 只更新 p
```

`--steps` 子采样时同样成立：规则是「第一个 `t <= commit_t` 的已选 timestep」。
没有候选的 OD 行永不 commit，直接退回 base 轨迹（`has_candidate=False`）。

## 6. 运行

```bash
# Step 1 骨架与图（含 overlay 可视化）
python scripts/data/10_build_skeletons.py --config configs/config_v2_skeleton.yaml

# Step 2 离线候选 + topology/progress 标签（约 2 分钟）
python scripts/data/11_build_skeleton_candidates.py --config configs/config_v2_skeleton.yaml

# Step 4 固定中心 IRIS 形状标签（约 5 分钟，100% 成功）
python scripts/data/12_build_skeleton_shape_labels.py --config configs/config_v2_skeleton.yaml

# 训练 / 采样 / 评估
python train_v2.py    --config configs/config_v2_skeleton.yaml
python sample_v2.py   --config configs/config_v2_skeleton.yaml \
                      --ckpt outputs/ckpt_v2_skeleton/best.pt --num 8
python evaluate_v2.py --config configs/config_v2_skeleton.yaml \
                      --ckpt outputs/ckpt_v2_skeleton/best.pt --runs 4 --max-candidates 4

# M = 1/2/4/8 ablation
for M in 1 2 4 8; do
  python evaluate_v2.py --ckpt outputs/ckpt_v2_skeleton/best.pt --max-candidates $M
done
```

## 7. 已跑通的实测结果

数据：`data/processed_scene_v1`（umaze/medium/large，train 17295 / val 961 / test 961）。

| 项目 | 结果 |
| --- | --- |
| skeleton / graph | umaze 3 nodes · 2 branches；medium 10 · 10；large 15 · 17 |
| 候选生成 | train：empty OD 122 (0.7%)，平均 valid 1.03；**绝大多数 OD 只有 1 条合法 topology** |
| topology 熵 | train 0.008 / val 0.010 / test 0.011（数据集本身近似单模） |
| fixed-center IRIS | 380 + 742 + 1108 个 skeleton 像素全部求解成功，标签 100% safe，约 100 ms/像素 |
| progress 标签 | 单调违例 0，`s_0=0`、`s_{K-1}=1` 全部成立 |
| 模型规模 | 6.43 M 参数（8 traj blocks + 2 refine blocks，d_model=128） |
| 训练速度 | ≈ 0.30 s/batch（batch=32, cuda），541 batch/epoch ≈ 2.7 min |
| 400 batch 后 loss | Lp 0.262→0.118，Lshape 0.775→0.452，Lsafe 0.634→0.403，Liou 0.781→0.676 |
| 400 batch 后评估 | traj_collision 1.00→0.80，ellipse_collision 1.00→0.38，**center_free 1.0000**，progress_violations 0，committed_at 7 |

> 重要发现：这三张 maze2d 地图的自由空间拓扑很稀疏，绝大多数 OD 对只有一条合法
> skeleton 路线（`mean_valid ≈ 1.03`，熵 ≈ 0.01）。因此 topology 选择在本数据集上
> 接近平凡，多模态几乎完全来自 `x_T` 的连续多模态；M=1/2/4/8 的 ablation 主要用来
> 验证「候选数不损害性能」，而不是展示巨大的 topology 增益。若要让 topology 选择真正
> 发挥作用，需要换成环结构更多的地图。
