### 续作发现的真实根因和修复

早期“主要由于模型不适应”的判断不充分。审查相同失败快照后发现，长直道路骨架仅保留远端结构节点，起点连接到车后方节点，使输入候选先倒退约 10–17 m。在线查询现在仅细分**已有**骨架像素链，保留原图几何/连通性，允许车辆在局部分支上接入；不把骨架当作 ego 执行曲线。

同时修复速度层错误：把下一 50 ms 可达到的速度当作速度 PID 的目标，会令自车持续以约 0.4 m/s 爬行。现在速度剖面表达速度约束，控制器单独限制加速度；等待阶段在前车前预留 18 m 机动空间，避免贴近障碍停车后再无换道空间。局部目标更新步长为 8 m，与实测异步延迟匹配。

**明确的推理适配，不能在论文中省略：**当前不再是“原 checkpoint 的 O/S/G 输出直接执行”。保留网络、学习的椭圆走廊、4-step DDIM、ALM 和原有终端 L1 安全投影，在**同一个终端投影**中额外加入起点/终点切向控制点条件、正向进度、控制多边形平滑度及车辆道路边界约束；目标仍是最小化与网络输出控制点的 L1 距离，原冻结走廊约束仍必须成立。没有第二个轨迹生成器，没有手绘换道曲线，没有采样另一规划器的输出替代模型。该适配由 `vehicle_constraints` 开关控制，默认离线训练/评估路径没有这些附加条件。

在线停车车占据膨胀仍为 **4 格 / 2.5 m**。点模型走廊的附加 `safety_margin` 由原训练配置 0.02 scene（1.6 m）明确改为 0.2 m；真实道路车身支撑条件单独加入投影，并由完整矩形 +0.15 m 的真实道路多边形验收把关。不能把这项变化隐瞒成原推理参数完全不变。车身道路内侧约束在路径中部增加支撑余量，起终点平缓过渡；所有输出仍通过原曲率、当前姿态、静态占据及动态包围盒检查。

道路 footprint 检查从粗栅格覆盖升级为 CARLA 真实车道多边形的完整矩形包含检查。相邻车道 float32 边界存在微米级缝隙，合并后使用 **0.1 mm** 数值容差闭合，不是扩大道路安全裕度；车身仍额外留出 150 mm。`acceptance_audit.json` 根据记录到的**实际车辆状态**独立核对每帧道路合法性和两辆 NPC 间距，不只核对候选路径。

前车使用 Mini Cooper 并在自己车道内靠右 0.65 m 停靠，仍占用 ego 原车道；NPC 路径与速度由确定性物理脚本控制。成功路段是 Town05_Opt、road 34 / lane 3 / s=60 m，已固定到配置，不再在正式运行时自动挑路或挑种子。

验证：25 项相关测试通过，包括原 ALM、默认可行解不变、可行/不可行车辆附加约束、骨架细分不改变几何、速度爬行、真实道路 footprint 和短目标。当前配置以 **1 Hz 提交规划请求**、最大候选年龄 1.8 s 运行；实际推理较慢，过时/策略不符/不安全候选照常拒绝。这里只验收了一个场景的一次完整成功应用，不能据此宣称高频实时性、所有动态场景安全或原网络独立具备动态安全能力。

## 已实现的系统行为

1. 主线程唯一拥有 `world.tick()`；20 Hz 仿真时间步，按墙钟节奏运行；记录循环超期次数。模型在独立串行线程运行，最多 1 个执行任务和 1 个可覆盖等待任务，不阻塞 tick 等待结果。
2. 固定全局目标、单调路线进度、按目标车道/5 m 进度维护稳定局部目标；最终终点附近不因近目标规则反复改变版本。
3. FOLLOW / PREPARE / WAIT_GAP / CHANGE / PASS / RETURN 状态，目标车道锁定、间隙稳定 0.4 s 后批准；模型路径才可能触发 CHANGE。持续停车和恢复移动使用滞回分类。
4. 基于同一 world snapshot 的位置/速度；静态车身属性启动后缓存，位姿逐 tick 更新。包围盒局部偏移用矩阵复制变换，避免 CARLA 原地 `Transform.transform(Location)` 导致跨帧漂移。
5. 安全验收包括源时间、目标版本、ALM/512 点验证、完整 footprint、合法路面、端点、当前航向/位置、曲率和恒速预测时空碰撞；左后车相对速度/制动距离独立检查。
6. 几何路径与速度分离：曲率、跟车、停靠、终端停止、前后向加减速度扫描；PP+PID 只通过 `VehicleControl` 控制。
7. 没有批准路径、动态风险、跟踪失配时制动；推理异常不替换路径。无手写换道曲线、Frenet/A* 替代车辆执行、ego autopilot 或每帧瞬移。
8. 真实 NPC 物理运动、碰撞传感器、场景/模型 hash、逐帧状态/控制/候选/验收 CSV、原始请求 NPZ、候选控制点 NPZ、事件日志、俯视轨迹 MP4、CARLA RGB MP4。RGB 与 HUD 用相同 frame ID 匹配，允许异步晚到。

配置中的 20 Hz 是仿真步长/目标节奏，不能用它声称墙钟实时性保证。当前预测是恒速世界坐标预测，不是可证明安全的多模态预测；曲线是生产 128 点解码后的弧长重采样，保留生产 512 点静态验证。在线动态检查为离散时间 OBB，尚未形成连续时间碰撞保证。

1. 模型在真实窄车道、4 cell 停车车膨胀的输入上出现 ALM/footprint 失败；模型只条件化 O/S/G，当前样本还表现出前端航向/曲率不适合车辆的问题。结合训练自由区被腐蚀扩大的事实，部署分布差异是合理根因推断，不能仅凭本次运行证明唯一根因。
2. 当前完整规划链路与 CARLA 同时运行时约 1 s，达不到初始 0.20 s 时效门槛。降低调度频率可排除“全被过时拒绝”，但不能解决第一项几何/可控性问题。

下一步应在保持既定安全约束的前提下，筛选并验证更宽的合法道路走廊、测量各推理阶段耗时及模型可控性；若需要改变允许车道集合或模型航向输入，应明确修改实验规格。不要悄悄腐蚀真实道路、降低膨胀、改换道曲线或重新定义成功。

## 运行方式

在 PowerShell 中，D/E 两个入口都可用，使用已有 GGMPC 环境：

```powershell
$py = 'E:/CondaEnvData/envs/GGMPC/python.exe'
$entry = 'E:/CarDataSample/Neural-IRISDiffuser/scripts/carla_online_closed_loop.py'
& $py $entry --mode inspect --no-video
& $py $entry --mode audit --no-video
& $py $entry --mode observe --duration 12
# 当前默认配置已固定为成功场景和公开记录的在线适配参数。
& $py $entry --mode drive
```

CARLA 需先启动并在 localhost:2000 提供服务；入口会按配置加载 Town05_Opt。默认运行目录带时间戳；`--out` 只接受不存在/空目录。每次保存 checkpoint hash、地图 OpenDRIVE hash、Git commit/dirty 状态及新增集成源码 hash，避免有未提交改动时仅用 commit 冒充精确来源。

实现时核对了 [CARLA 0.9.16 Python API](https://carla.readthedocs.io/en/0.9.16/python_api/) 和本机同版本 `agents/navigation/global_route_planner.py`。上述性能和失败数据以本地保存的日志为依据。
