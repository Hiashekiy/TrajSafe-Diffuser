# 稳定版本冻结与继续训练说明

本文记录当前效果较好的 V1 联合扩散版本，以及后续实验、继续训练和回退时的推荐操作。

## 1. 当前稳定版本

- 稳定提交：`3236983 release: freeze center-balanced training config`
- 稳定标签：`v1.0-center-balanced`
- 当前训练配置：`configs/config_v1.yaml`
- 当前批大小：`64`
- 稳定模型：`outputs/ckpt_v1_smooth_iou_free_cvar_center_balanced/best.pt`
- 模型来源：epoch 99（代码内部从 0 开始计数，即第 100 个 epoch）
- 模型 SHA-256：`39648E95F7207B9449CA497CD0AB82C05896504549F4248FD0AB2B07C5142B1E`
- 数据压缩包 SHA-256：`AD525A894D2FA5BCADA27DE0C002B4BE7C59220159B69ED6D6E91064361C7512`

当前损失配置的关键参数如下：

```yaml
lambda_e: 1.0
lambda_smooth: 0.1
smooth_acc_weight: 0.25
smooth_jerk_weight: 1.0
lambda_iou: 0.25
lambda_safe: 0.1
safe_cvar_fraction: 0.2
safe_cvar_weight: 1.0
ellipse_safe_res: 64
```

其中安全损失采用“整体均值 + 每条轨迹最差 20% 椭圆的 CVaR 均值”；IoU 仍使用普通平均。椭圆中心使用轨迹点时对轨迹坐标执行了 `detach`，因此椭圆损失不会直接通过坐标关系修改轨迹输出，但仍会通过共享 Transformer 参数影响共享特征。

## 2. 标签、分支和切换的区别

当前同时使用了标签和分支，但用途不同：

- `v1.0-center-balanced` 是稳定版本标签。它固定指向提交 `3236983`，用于长期标记和准确回退，正常开发中不应移动该标签。
- `codex/next-joint-diffusion` 是后续实验分支。它目前也从 `3236983` 起步，但以后会随着新提交向前移动。
- 创建分支并不等于切换分支。目前工作区仍位于 `master`；只有执行 `git switch codex/next-joint-diffusion` 才会真正切换。

推荐关系如下：

```text
v1.0-center-balanced（固定标签）
             |
             v
3236983（稳定代码和配置）
             |
             +-- master
             +-- codex/next-joint-diffusion（后续实验从这里继续）
```

## 3. 开始后续实验

先确认工作区状态：

```powershell
git status --short --branch
```

当前仓库存在一个与本次版本冻结无关的本地删除：

```text
D data/processed_scene.zip
```

切换分支不会主动清除该修改，但在提交前必须确认是否真的要删除这个文件，避免把无关变更混入实验提交。

切换到实验分支：

```powershell
git switch codex/next-joint-diffusion
```

以后对网络、损失或配置的修改都在该分支提交。这样即使实验效果退化，稳定标签仍保持不变。

## 4. 继续训练 100 个 epoch

继续训练使用独立配置：

```text
configs/config_v1_continue.yaml
```

该配置具有以下特征：

- 从 epoch 99 的 `best.pt` 恢复优化器和模型状态；
- `train.epochs` 设置为 `200`，因此实际继续执行 epoch 100～199，共 100 个 epoch；
- `batch_size` 为 `64`；
- 输出到新的目录，不覆盖稳定模型：
  `outputs/ckpt_v1_smooth_iou_free_cvar_center_balanced_continue100`。

训练命令：

```powershell
E:\CondaEnvData\envs\GGMPC\python.exe train.py --config configs/config_v1_continue.yaml --resume outputs/ckpt_v1_smooth_iou_free_cvar_center_balanced/best.pt
```

注意：这里的 `epochs: 200` 表示训练结束时的总 epoch 数，不是额外训练 200 个 epoch。

## 5. 回到稳定代码

只想临时查看或测试稳定版本时，可以创建一个临时分支：

```powershell
git switch -c codex/recheck-v1 v1.0-center-balanced
```

如果当前分支有未提交修改，先提交、暂存到 stash，或者明确处理这些修改；不要使用 `git reset --hard`，否则可能丢失本地工作。

也可以让现有实验分支重新基于稳定标签开始，但这会改写分支状态，执行前应先创建备份分支。一般更安全的做法是从标签新建分支：

```powershell
git switch -c codex/new-experiment v1.0-center-balanced
```

## 6. 将稳定版本推送到远端

当前稳定提交和标签只在本地时，磁盘损坏仍可能导致丢失。确认无误后分别推送：

```powershell
git push origin master
git push origin v1.0-center-balanced
git push -u origin codex/next-joint-diffusion
```

不需要使用强制推送。

## 7. 模型和数据必须单独备份

`.gitignore` 已忽略 `outputs/`、生成的数据目录以及 `data/processed_scene_v1.zip`。因此：

- Git 标签可以恢复代码、配置和本文档；
- Git 标签不能恢复 `best.pt`、训练日志、测试图片或生成的数据集；
- 不要把数百 MB 的模型或数据直接提交到普通 Git 历史，GitHub 单文件上限会使推送失败；
- 应将稳定模型和对应数据存入独立备份、Git LFS、DVC 或发布附件，并保留本文列出的 SHA-256。

在 Windows PowerShell 中校验模型：

```powershell

```

输出应为：

只有代码标签、训练配置、模型文件和匹配的数据集都保留，才算能够完整复现实验。
