# 修正方案：顺序式「先轨迹后椭圆」网络 + 局部 256→64（已定稿）

> 状态：**已按你的确认定稿**。以下方案为最终实现蓝图，尚未改动代码。逐条确认你的决策已写入，无需再改；后续我按此实现。

## 一句话总结

把当前「在 S_t 后分出 EllipseHead 分支」的**并行**结构，改成**顺序式**：

1. 先用 **S_t**（保留不动）解码出**轨迹** p̂；
2. 再用预测出的轨迹 **p̂** 去采样局部地图（**第二次采样**，第一次仍用输入的噪声轨迹 pos_t 采样给解码器）；
3. 最后用**局部地图特征 + set-attention 聚合**，直接对椭圆标签回归，**center = p̂ + Δ**，**不喂 F_traj**。

同时把局部特征分辨率从 **256×256 → 64×64**（全局 memory 仍 16×16，**输入 map 不降采样**，只是解码不恢复到 256）。

训练三阶段：阶段1 只训轨迹 → 阶段2 **冻结**骨干只训椭圆 → 阶段3 联合微调。

本质：**把当前网络去掉椭圆预测头，用作轨迹预测；后面再接一段椭圆预测网络。**

## 1. 目标与动机

- **依赖问题**：当前椭圆头在 S_t 处分叉，S_t 融合的是「z_t 算出的**噪声位置** pos_t」处的局部特征。椭圆一开始学的时候采样位置是乱/不准的，椭圆学不好（尤其 orientation 卡在 ~50°）。
- **解耦训练**：先训好轨迹，轨迹给出**可信 p̂**，再用 p̂ 采样做椭圆，椭圆学到的是「贴着真实路点的局部几何」。
- **简化 / 少混信息**：椭圆是**逐路点局部几何体**，直接对椭圆标签回归；不强制 center≈p̂、theta≈切线；也不需要整条序列的全局特征 F_traj。
- **省显存 / 贴尺度**：local 256×256 → 64×64（内存约降 16 倍），9×9 窗口**实际空间范围约×4**，更贴合椭圆尺度。

## 3. 修正后总体架构（顺序式，最终）

map_tensor [B,1,256,256]
      │  （输入保持 256，不降采样）
      ▼
SceneEncoder[local_res=64] ──► memory [B,C,16,16]       [冻结段]
        │                     └─ local  [B,C,64,64]     [冻结段]
        │
        ├─ memory+位置 → scene_tokens → cond_mem = [h_start; h_goal; scene_tokens]
        ├─ local+位置  → loc_pe [B,C,64,64]
        │
z_t, t ──► TrajectoryEncoder ──► F_traj [B,N,C]         [冻结段]
        │
        ├─ 【采样①】local_sampler(loc_pe, pos_t[:,1:])  (输入噪声轨迹) ──► [B,N,81,C]
        ├─ PointSceneAttention(F_traj, local) ──► A_t
        ├─ SafetyFusion(F_traj, A_t) ──► S_t            [保留，供解码器]
        │
        └─ TrajectoryDecoder(S_t, cond_mem) ──► T_t ──► ResidualHead ──► z0_raw
                  │
                  └─ zero_sum → z0_proj → p̂ = integrate(start, base + z0_proj)  [B,H,2]  ★轨迹
                              │
                              ▼  【采样②】用预测轨迹 p̂ 采样局部
        local_sampler(loc_pe, p̂[:,1:]) ──► [B,N,81,C]
                 │
                 ▼  EllipseAggregator（set-attention，81→C）
        e_k [B,N,C]
                 │
                 ▼  EllipseHead(e_k, p̂)
        center = p̂ + Δ ; r1, r2, dir, theta           (对椭圆标签直接回归)

**要点**：
- S_t **保留**，仍喂给 TrajectoryDecoder（不拆 S_t，只把椭圆分叉从 S_t 挪走）。
- **两次采样**：采样①用输入噪声轨迹 `pos_t`（因为此时还没预测出轨迹），给解码器；采样②用预测轨迹 `p̂`，给椭圆。
- 椭圆段**不再吃 F_traj**，也不从 S_t 分叉；是一个**以局部地图特征为输入的逐路点几何回归器**，`center = p̂ + Δ`。

## 5. 场景编码（SceneEncoder：输入 256，local 只到 64）

### 现状
- SceneEncoder(d_model=128, enc=(32,64,96,128,128), res=256)：输入 256 → 下采样到 **16×16** bottleneck → 上采样到 **256×256** local。

### 改为
- 新增配置 `model.local_res: 64`。
- **输入 map_tensor 保持 256**（不降采样；保留编码器细节）。U-Net 下采样路径不变：256→128→64→32→16，bottleneck **16×16**（memory 不变）。
- **解码器只上采样到 64**（16→32→64，2 次上采样），`local` 输出 **64×64**。不再恢复到 256。
- 输出：memory `[B,C,16,16]`（全局）、local `[B,C,64,64]`（局部）。

### 影响
- local 张量：`[B,128,256,256]` → `[B,128,64,64]`，内存约降 16 倍。
- 编码器下采样路径仍处理 256（保留全局细节），只是**省掉 64→128→256 这后半段上采样**，算力降。
- memory 仍 16×16，全局粒度不变。

### 局部窗口实际尺度
- res=64：9 格跨度 = 9×(2/64) = 0.2813 场景单位，**约放大 4 倍**（对比 res=256 的 0.0703）。
- 更能覆盖「路点两侧自由空间宽度」，更贴椭圆尺度，预计对半径/方向有利。

## 9. 轨迹解码 → z0 → p̂

- TrajectoryDecoder(S_t, cond_mem)：4 层 nn.TransformerDecoderLayer（norm_first）。
- ResidualHead(T_t) → z0_raw [B,N,2]。
- **新增**（forward 内）：
  z0_proj = zero_sum(z0_raw)
  pos_pred = integrate_positions(start, base + z0_proj)   # [B,H,2]
  p̂ = pos_pred[:, 1:]  （去掉起点，与椭圆逐路点对齐）

## 10. 椭圆生成（顺序式，采样②在 p̂，center=p̂+Δ）

### 输入
- loc_pe [B,C,64,64]（同一份局部特征 + 位置编码）。
- p̂ = pos_pred[:,1:]（预测轨迹中间点）。
- **不再用 F_traj**，**不再从 S_t 分叉**。

### 流程
local_b = LocalSceneSampler(loc_pe, p̂)        # [B,N,81,C]
e_k     = EllipseAggregator(local_b)           # set-attention: 81→C
ellipse = EllipseHead(e_k, p̂)                  # center = p̂ + Δ, 其余同现 head

### EllipseAggregator（新增，set-attention）
- 每路点一个**可学习 query**，对 81 个窗口 token 做 1~2 层 cross-attention + FFN，聚合成 e_k [B,N,C]。
- q = learnable [C]（expand 到 [B,N,1,C]），kv = local_b [B,N,81,C]。
- 窗口 token 已带**绝对地图位置编码**（loc_pe=local+map_pos），模型可从窗口各格子的绝对位置恢复出「窗口中心在哪、自由空间往哪伸展」，无需额外注入 p̂ 或相对坐标（符合你「不要混多余位置信息」）。

### EllipseHead（改输入）
- e_k [B,N,C] → MLP → raw[B,N,6]。
- `center = p̂ + Δ`，其中 `Δ = raw[...,0:2]`（偏移）。
- 半径 softplus+1e-6，max/min 排序 r1≥r2；方向向量归一化；theta=0.5*atan2。
- **不强制 center≈p̂ 是假设**——Δ 完全由标签学出；只是用 p̂ 作**锚点参数化**，更易收敛。

### 为什么不合 F_traj
- 椭圆是局部几何体：形状（半径/方向）由路点周围自由空间决定，位置锚点由采样位置 p̂ 给出。
- 整条序列全局语义 F_traj 对「单个路点椭圆」贡献小，反而混进全局轨迹信息、加大方向学习难度。**确定去掉**。

## 12. 损失函数（分阶段）

### 轨迹相关（不变）
- L_Z（MSE zero_sum 投影）、L_p（中间位置 MSE）、L_smooth（二阶差分 Huber）、L_col（SDF softplus，SDF 仍 256）。
- L_axis（把预测轨迹拉向预测椭圆长轴，近圆掩码）：**保留**，在 joint 阶段用 pos_pred。阶段2 可用冻结的 pos_pred 作辅助（见 §13）。

### 椭圆相关（公式不变，来源改）
- L_param：L_center(SmoothL1) + L_radius(MSE) + L_theta(双角向量 MSE)，对椭圆标签 center/r1/r2/Q 回归。
- L_iou：预测椭圆掩码 vs GT 椭圆的软 IoU（grid_n=21）。
- 输入张量 = 新椭圆头输出（字段名不变），center 已是 p̂+Δ 的绝对坐标。

### total_loss 改动
- 用 `model_out["pos_pred"]`（不再内部复算）；椭圆分支字段名不变。

## 13. 训练阶段与冻结机制

### 阶段1：--phase traj（轨迹）
- 损失：total = lambda_z*L_Z + lambda_p*L_p + lambda_s*L_smooth（+ 可选 L_col 按 ramp）。
- **不计算/不回传椭圆损失**（椭圆模块存在但不训练；forward 会算，但无梯度，参数不动）。
- 目标：把轨迹训稳（后续椭圆的前提）。

### 阶段2：--phase ellipse（冻结骨干 + 训椭圆）
- **冻结**：scene_encoder, trajectory_encoder, local_sampler(无参), point_scene_attention, safety_fusion, trajectory_decoder, residual_head, map_pos_embed, type_embed。
- **只训**：ellipse_aggregator, ellipse_head。
- 前向仍跑完整网络（冻结骨干给出确定性 p̂），只对椭圆模块求梯度。
- 损失：total = lambda_e*L_param + lambda_iou*L_iou（可含 L_axis，用冻结 pos_pred 作长轴参考）。
- 实现：
  for name, p in model.named_parameters():
      if phase=="ellipse" and name.startswith(冻结前缀): p.requires_grad = False

### 阶段3：--phase joint（联合微调）
- **解冻全部**，损失 = 轨迹 + 椭圆 + 轴对齐 + 碰撞全量，协调轨迹与椭圆。

## 17. 预期收益 / 风险

- **收益**：椭圆在可信路点采样，几何更准，重点解决 orientation 卡住；结构更简单（椭圆只吃局部）；局部降采样省显存/算力且窗口更贴椭圆尺度；三阶段解耦符合“先轨迹后椭圆”。
- **风险**：解码器仍用噪声位置 pos_t 采样做 S_t（现状，未改）；若 local_res=64 局部不够细可回调 128；local_window=9 在 64 下窗口变大，过大可调 5/7；阶段2 椭圆只依赖冻结 p̂，故阶段1 轨迹要训稳。
