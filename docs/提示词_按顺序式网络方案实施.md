注意当前网络的现状（方案要改变它）：
- 现在**并行**：在 `S_t` 处分出 `EllipseHead` 和 `TrajectoryDecoder`；椭圆头输入是 `S_t`。
- 局部特征 `local` 是 `256×256`。
- 没有 `EllipseAggregator`。
- 椭圆中心是**绝对坐标**（不是 `p̂+Δ`）。
- 椭圆 loss 目前是 `param / iou / axis`，没有 `ecoll / anchor`。

## 二、要实现的目标结构（顺序式）

主链：
`map → SceneEncoder{memory 16×16, local 64×64}；z_t,t → TrajectoryEncoder → F_traj；z_t→integrate→pos_t(noisy)→Sampler#1→Local_1；F_traj+Local_1→PointSceneAttention→A_t；F_traj+A_t→SafetyFusion→S_t；S_t+C→TrajectoryDecoder→z0_raw→zero_sum→pos_pred(p̂)；p̂→Sampler#2→Local_2；Local_2+PE_rel→EllipseAggregator(set-attn)→e_k；e_k+p̂_k→EllipseHead→E_k。`

要点：
- `S_t` 保留，只服务轨迹解码器；**不再从 `S_t` 分叉椭圆**。
- **两次采样**：①用 `pos_t`（输入噪声轨迹）给轨迹；②用 `p̂`（预测轨迹）给椭圆。
- ellipse 分支只用 `Local_2 + PE_relative`；**不用**绝对位置 PE、`F_traj`、`S_t`、`scene_tokens`、`start/goal`。
- 椭圆中心 `c_k = p̂_k + Δc_k`（head 输出偏移 `Δc = raw[..., 0:2]`）。
- **Phase 3 不能 `detach(`p̂`)`**（要让 `L_ellipse` 反传到轨迹网络）。

## 三、具体改动（映射到文件）

1. `configs/config.yaml`：`model` 下加 `local_res: 64`、`ellipse_aggregator_layers: 2`；新增 `ellipse_loss` 区（`lambda_param=10, lambda_iou=5, lambda_coll=2, lambda_anchor=5, soft_mask_tau=10, near_circle_angle_mask: true`）；加 `joint_ellipse_ramp`（比例建议 0.2）与各阶段 lr。
2. `src/models/scene_encoder.py`：输入仍 `256`；下采样到 `16×16` bottleneck；`memory` 仍 `16×16`；**解码器只上采样到 `local_res=64`**（16→32→64），**不要恢复到 256**。输出 `memory[B,C,16,16]`、`local[B,C,64,64]`。
3. `src/models/local_scene_sampler.py`：`res` 参数用实际 `local_res`（影响窗口 offset）。
4. `src/models/ellipse_aggregator.py`（新增）：set-attention，2 层，**共享 learnable query**，对 81 个局部 token（`Local_2 + PE_rel`）聚合 → `e_k[B,N,C]`。每层 `LN→CrossAttn→Residual→LN→FFN→Residual`。
5. `src/models/position_encoding.py`：已有 `Sinusoidal1D/2D`。为 ellipse 加**相对**编码：分别编码 `Δx`、`Δy`（脚本里对连续坐标按 `sin/cos` 频次编码，再拼接投影到 `C` 维），累加到 `Local_2`。**注意（很重要）**：`Δx/Δy` 是很小的值（窗口约 ±0.125 场景单位），直接用默认 `base=10000` 的 `sin/cos` **频率太低、几乎区分不开**。要像 `Sinusoidal2DPositionEmbedding` 的 `scale=128` 那样，先给 `Δx/Δy` 乘一个**放大系数 `scale`**（建议读配置，或先用 ~100/128 量级），再做正弦编码，保证小偏移也有足够频率分辨。可参考现有 `Sinusoidal2DPositionEmbedding` 对连续坐标加 `scale` 的做法。
6. `src/models/planner.py`：构造上同 1；`forward` 改顺序式（见二）。返回 `z0_pred, pos_pred, ellipse_center, ellipse_radii, ellipse_dir, ellipse_theta`；去掉 `S_t` 分叉椭圆。
7. `src/models/ellipse_head.py`：输入改为 `(e_k, p̂)`；输出 `raw[B,N,6]=[Δx,Δy,ρ1,ρ2,u,v]`；`center=p̂+Δ`；半径 `softplus+sort`；方向归一化；`theta=0.5*atan2`。
8. `src/losses/ellipse_loss.py`：按方案新增/调整——`L_param`（center SmoothL1 / radius MSE / angle 双角 MSE）、`L_iou`（soft mask `τ=10`，soft IoU）、`L_ecoll`（预测椭圆 soft mask 与障碍重叠惩罚）、`L_anchor`（`ReLU[(p̂-c)^T Q (p̂-c) − 1]`，`x0=p̂`）；近圆 mask 用于 angle。把现有 `ellipse_axis_loss` 重构为 `L_align`（`1−|v_k^T a_k|`，近圆 mask），放 joint。
9. `src/losses/total_loss.py`：改用 `model_out["pos_pred"]`；按 phase 组装：`Phase1=L_traj`；`Phase2=L_E`；`Phase3=L_traj+λ_E L_E+λ_align L_align`（λ_E 走 ramp）。
10. `train.py`：加 `--phase traj|ellipse|joint`；`Phase2` 冻结轨迹骨干（scene_encoder / trajectory_encoder / local_sampler / point_scene_attention / safety_fusion / trajectory_decoder / residual_head / map_pos_embed / type_embed），并对其 **eval() 关 dropout**（保证 `p̂` 确定），只训 `ellipse_aggregator + ellipse_head`；可选 local decoder 末尾 1~2 层用 `0.1×LR` 微调；`Phase3` 全部解冻 train()，不 detach `p̂`，`λ_E` 线性 ramp。
