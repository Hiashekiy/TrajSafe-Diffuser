## 3. 四条结论

1. **六个"逐点约束"方法在密集障碍场景上几乎无差别。** RoS / ReS / Projected / ALM 撞墙的场景集合与
   无约束基线**逐字相同**（5 个场景全中），平均最小净距只是从 +1.43 m 抬到 +1.9…+2.4 m。这不是实现问题，
   是 §A3 的预测：它们约束 128 个顶点，评价器量整条折线，顶点全安全而线段照样切角。
2. **TVS 是唯一全覆盖的，原因机制化的**：TVS 的时变水平在低噪声段要求额外余量（我们换算为一个栅格
   0.125 m），相当于把安全集**收紧**了；RoS/ReS 的松紧都在同一条零水平线附近。所以 TVS 的胜出来自
   "更严的约束"，不是"更好的 QP"。
3. **PDM 是唯一从机制上解决"线穿墙"的方法**（App. C.3 段约束，46k 行），17 个返回场景 0 撞墙；
   代价是**长度比 3.025**（路径被投影拉扯变形）和 3 个场景判不可行（残差 0.060 / 0.075 / 0.090 收不到
   1e-6）。这三点必须一起报，不能只报 0 撞墙。
4. **Primal-Dual 是唯一明显改变路径形状的乘子法**（长度比 2.245，修好 87040 但撞墙数只从 5 降到 4），
   代价与收益都比 ALM 大 —— 与两篇论文的定位一致。

## 4. 三条必须一起说的限制

1. **TVS 的数字完全依赖 `sd_tvs_level_scene=0.125`。** 这个数是"官方归一化坐标里 1 个障碍半径 ↔ 我们一个
   栅格"的换算，不是论文给的。**必须做一次敏感性**（0.05 / 0.125 / 0.25），否则 TVS 的 0/20 不可信。
2. **PDM 的 3 个失败是我们的守卫触发的**：官方在这种情况下会无限重投（`while violation:` 无上限）。我们
   加了 `pdm_max_retries` 和"交付前必须真可行"的检查，所以记 FAILED 而不是交付一条残差 0.09 的路径。
   报告里要写成"17/20 可行 + 3/20 未收敛"，不能写成"3/20 崩溃"。
3. **val、20 场景、单种子**。这不是 test 集结论，也不能跨种子比较（口径红线 §8.5–8.6）。
