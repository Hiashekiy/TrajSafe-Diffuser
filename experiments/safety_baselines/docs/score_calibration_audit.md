# Score 标定审计（x0 预测 → score）

本轮没有重新训练任何模型。审计对象是现有共同基座（`map_only_point_diffuser_v1`，256 级 cosine VP，x0 预测目标）
在 VP 前向过程下换算出的 score。

## 1. 换算与限定语（必须先读）

```
ε̂(x_t,t) = ( x_t − √ᾱ_t x̂0(x_t,t) ) / √(1−ᾱ_t)
ŝ(x_t,t) = − ε̂ / √(1−ᾱ_t) = − ( x_t − √ᾱ_t x̂0 ) / (1−ᾱ_t)
```

这是**条件**噪声/条件 score 的换算。`x_t = √ᾱ x0 + √(1−ᾱ) ε` 的单样本条件 score
`∇_{x_t} log q(x_t|x_0)` 与数据边缘 score `∇ log p_t(x_t)` 只有在 `x̂0 = E[x0|x_t]`（条件均值最优）时才一致。
因此下表的 "ε̂−ε RMSE" 与 "cos(ε̂,ε)" 是**条件噪声估计误差**，不能直接称为边缘 score 精度。
论文里若要写"score 质量"，必须带上这句限定。

## 2. 测量方法与数据

- 20 个 val 案例，同一噪声向量（`torch.Generator(seed=0)`），5 个噪声等级 `t ∈ {0, 64, 128, 192, 255}`。
- 指标：`ε̂−ε` 的 RMSE、`cos(ε̂,ε)`、`‖ŝ‖` 的逐样本中位数、x0 RMSE（raw 与 decoded）。

## 3. 三个结论

1. **高噪声段"看起来准"是退化的**：σ 远大于数据尺度时 `ε ≈ x_t/√(1−ᾱ)` 几乎解析可得，cos→1、ε RMSE→0 不代表学到了分布。
2. **低噪声段条件 score 方向很差**：t=0 时 cos 只有 0.359，范数却高达 3.2e3 —— 因为除以 `√(1−ᾱ_0)=0.0137` 把 4.1 m 的 x0 误差放大了 73 倍。这不是数值 bug，是 x0 目标本身在末端的分辨率。
3. **对 Langevin 类方法的直接影响**（把上面两项换成步长）：
   - CD：`β_0/2·‖s‖ ≈ 9.4e-5 × 194 ≈ 0.018 scene = 1.5 m`／步，噪声 `√β_0 = 0.0137 scene = 1.1 m`；
   - PDM：`γ_0·‖s‖ ≈ 3.1e-5 × 194 ≈ 0.006 scene = 0.5 m`／步。
   两者都与 **waypoint 间距 0.95 m** 同量级，因此末级的 Langevin 残差会把交付折线"打毛"——这与实测 CD 长度比 2.7–4.7（PDM 5.4）一致，也与"无约束 DDIM 长度比 0.99"形成对照（DDIM 末步直接输出 clean）。

## 4. 能不能用这个 score 做 PDM/PD/ALM？

- **可以用作任务适配的 score**：中高噪声段方向可靠，Langevin 的主体混合发生在这些段。
- **不能声称等价于论文的 score-matching 模型**：PDM 原文用的是 score matching 目标并明确讨论过训练目标的影响（App. G）。本基座是 x0 MSE + 辅助项，末级分辨率受 x0 误差限制。
- 需要 score-matching 模型时应单独提交方案（训练目标、噪声日程、与七种方法的公平性说明），本轮不做（任务书 A5 的要求）。
