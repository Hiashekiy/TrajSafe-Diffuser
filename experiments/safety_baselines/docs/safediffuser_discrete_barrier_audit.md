# SafeDiffuser 离散 barrier 审计（Phase E）

对象：`algorithms/safediffuser/runner.py`，RoS / ReS / TVS 三种。
数据：`results/phase_e_safediffuser/discrete_barrier.jsonl` + `discrete_barrier_summary.json`，
以及解析单圆测试 `tests/test_phase_e_safediffuser.py`（4 项）。

## 1. 原论文条件与实际更新

论文（eq 7/8/12）给的是**速度条件**：

```
grad h(x) · nu + eps (h(x) - gamma) >= 0
```

而实际施加的更新是 `x <- x + dt·nu`，所以"速度条件成立"不等于"更新后状态安全"。

## 2. 任务书 E2 的离散证书

```
h(x_{k+1}) - gamma >= exp(-eps·dt) (h(x_k) - gamma)
```

实现方式：**按扩散级**检查（不是按微步），失败则把该级的 `cbf_dt` 减半重积分（最多 `cbf_level_retry` 次），
每次记录 `discrete_residual_end / level_attempts / discrete_ok / min_h_scene`。**QP 目标与 barrier 都没改。**

## 3. 三种实现途径的实测（3 个 val 案例，同一初始噪声）

|方案|结果|耗时|判定|
|---|---|---|---|
|逐微步回溯（8 次减半 + 拒步）|最大侵入 **176.66 m**（比不检查的 36.43 m 更差），532,639 次回溯、634 次拒步|180 s（超时，PDM 预算被打满）|**否决**|
|逐微步 + 近可行门 `min(h)≥-0.02` 才检查|侵入 35.91 m（对照 36.43 m），28,918 次回溯、752 次拒步|11.2 s|**否决**（几乎无改善、开销翻倍）|
|**按级检查 + 有限重试（现行）**|侵入 36.44 m，761/768 级证书不通过|7.1 s（+0 s）|保留为**监测**|

原因（解析）：证书对速度的要求是 `J v >= gamma - h`，**与 dt 无关**；把一个不满足速度要求的步长减半，要求的
速度不变，所以减半永远修不好。高噪声级别又必然远不可行（`h` 可达 −36 m），据此拒绝更新会让轨迹冻结在主噪
声尺度上（实测 −122 m 净距）。这与论文"violations 随 t→0 递减"的渐近语义一致，但与"每步都安全"不是一回事。

## 4. 解析单圆测试（`tests/test_phase_e_safediffuser.py`）

单圆 R=0.2、一个自由 waypoint、nominal 直接指向圆心：

|测试|断言|结果|
|---|---|---|
|远离障碍|不需重试、证书全部通过、末态净距 > 0.2|通过|
|nominal 指向圆心|离散检查开启后净距 ≥ −1e−6，且不差于关闭时|通过|
|`cbf_dt=4`（大步长）|要么净距 ≥ −1e−6，要么明确报错|通过|
|QP 不可行|必须抛 `SolverFailure/RuntimeError`，不得静默输出|通过|

即：**证书在近可行区间内是有效的**，问题在于高噪声段无法靠它补救。

## 5. 顺带确认的两件事

1. `cbf_max_point_step=0.001953125`（0.156 m/微步）仍然主导积分：`cbf_substeps` 16→1 结果不变（旧审计）。
2. TVS 的 `sigma_dot = -min(h0,0)/(N·dt)` **符号正确**（j 随逆扩散递减），本仓库此前"可疑"的判断已撤回。

## 6. 结论

- SafeDiffuser 三种在当前基座上**不可能**通过"每级离散证书"变安全：交付侵入 36 m 源自高噪声级别，
  而高噪声级别上一阶条件没有意义、减步长也无法修复。
- 若要真正改善，只有三条路（都改变算法或任务，需授权）：
  (a) 在每级末尾对状态做**投影**到可行集（这会引入 PDM 式的投影，等于改方法）；
  (b) 让 CBF 从**可行初值**出发（先投影初始噪声）；
  (c) 把 `Δτ` 真正做小（需要模型级数 ≫ 256，或每级内多次 RHS 且 ε·Δτ ≪ 1）。
- 已保留为**监测项**：任何交付轨迹的 `levels_discrete_bad` 都会出现在逐级 trace 里，不会被静默忽略。
