## 3. 逐行诊断

### 3.1 SafeDiffuser 三行：CBF 在本仓库的标度下数值不生效

三行与 Diffuser 的指标**逐位相同**（净距差异 < 1e-5 m），即修正量恒为 0。
根因在 `algorithms/solvers.py:cbf_velocity`：标量 `w` 在目标函数里以 `1/(2w²)` 出现

```
min .5||z - v||² + .5·||min(Jz+offset,0)||² / w²
```

`w = relax_weight = 100` ⇒ 松弛惩罚系数 `5e-5`，比速度偏差项小四个量级 ⇒ QP 宁可违约也不纠正。

四种标度全部试过（都在 3 个场景上实测）：

| `w` | 路径 | 结果 |
|---|---|---|
| 100（当前） | L-BFGS-B 消元 | 松弛几乎免费 ⇒ **不生效**（≡ 基线） |
| 0.01 | L-BFGS-B 消元 | `qp_relaxed_residual_failed`（耦合问题消元后不收敛） |
| 0（硬） | OSQP 硬约束 | `qp_fixed_condition_infeasible` / `qp_maximum_iterations_reached` |
| 显式软约束 QP（`SC48ControlTask.cbf_solve`, ρ=1e4, eps=1e-9） | OSQP 256 行 × 220 变量 | 单样本 **> 180 s 超时** |

结论：**控制点空间的 CBF 不是"调参"能救的**——硬系统结构性不可行（`J` 稠密，一个控制点影响 128 个
曲线点），软系统要么免费要么不可解。点空间之所以能用，正是因为它的约束行可分离（每个点只影响自己）。

### 3.2 Projected：最近点投影在控制点空间达不到精确可行

投影 `h(B·Q) ≥ 0` 对 `Q` 是**逐段仿射**的，所以最近点投影本质是 QP。已把 `CurveControlTask` 的 SLSQP
换成"OSQP + 信赖域 + 单调线搜索"的 SQP（`adapters/sc48_control.py:project`），残差从
`SLSQP 的 8.5 / 42.9 m` 降到 `0.87 m`，但 20/20 仍达不到 `projection_tol=1e-6`。

原因：要同时满足 128 条曲线点约束，48 个控制点能提供的自由度（46×2=92）远小于约束数，且端点被钉死；
最小距离解经常落在"某几条约束互相冲突"的点上。这不是收敛问题，是**可行性问题**——
需要把约束放松到"整段"或减少约束点，两种都会改变方法。

### 3.3 Primal-Dual / ALM：控制点空间里数值发散

20/20 碰撞、净距 −9.4/−9.6 m、长度比 5.1–5.2、最大曲率 125–147 1/m、二阶差分 0.17 m（基线 0.0023 m）。
即交付曲线剧烈振荡。直接原因：乘子梯度 `λᵀJ` 在控制点空间对**每个控制点**汇集 128 个曲线点的贡献，
比点空间的"每点一行"放大约 128 倍；`dual_constraint_scale=128` 与 `η=1e-3/s²`、`ρ=2.5e-4/s²`
这套点空间反算出的系数在控制点空间不再等价。

正确处理需要按 `J` 的量级重新推导乘子缩放（属于"改公式"，需单独授权），本轮**没有**为了出数而调它。

### 3.4 PDM：投影失败 + SGLD 漂移过大

`pdm_inner=20` 步 SGLD 后目标离可行集太远（残差 200–700 m），投影无法回收。
与 3.2 同一根因（控制点空间可行性），且 PDM 的 segment 约束**不能**直接加在相邻控制点上
（控制多边形 ≠ 曲线，见 `docs/sc48_recovery_audit.md` §5.4），本轮用的是曲线点约束口径。

## 4. 这不是本次引入的问题：历史 curve_control 实验同样失败

同一仓库 2026-11-13 的三次 `seven_curve_control_validation*` 运行（基座 = 点模型
`map_only_l1_final8`，同样是控制点空间）实测：

| 方法 | 历史 ok 数（v1 / v2 / v3） | 本次（S-C48） |
|---|---|---|
| RoS / ReS / TVS | 0/4 · 0/4 · 0/4 | 20/20（但见 3.1，是不生效） |
| Projected | 0/4 · 0/4 · 0/4 | 0/20 |
| PDM | 0/4 · 0/4 · 0/4 | 0/20 |
| Primal-Dual / ALM | 4/4 · 4/4 · 4/4 | 20/20（但发散） |
| Diffuser | 4/4 · 4/4 · 4/4 | 20/20 |

即：**控制点空间对七种方法本来就只有"Diffuser + PD/ALM"能跑**，而 PD/ALM 在 S-C48 上进一步失稳
（可能因为 S-C48 的 x0 更准 ⇒ 名义跳变更大 ⇒ 乘子更易爆，未验证）。
本次唯一的**改进**是把 SafeDiffuser 三行从"硬 QP 直接报错"变成"能返回"（软 QP），
但代价是它不生效——两者都不是可用的安全保证。

## 5. 结论

1. **方案 B 的对比表已经出来，但结论是负面的**：七种循环搬到 S-C48 的控制点空间后，
   没有一种能给出优于 S-C48 自身 DDIM 基线的结果；4 种直接失败，2 种发散，1 种（SafeDiffuser）
   因松弛标度问题等于关闭。
2. **S-C48 仍是更好的生成器**（2/20 碰撞、+3.5 m 净距、16 NFE、0.68 s），这一点在
   `docs/sc48_recovery_audit.md` 已确认。问题不在基座，在**安全循环的求解器假设**：
   它们全都假设"状态变量与约束行一一对应"，而 B 样条控制点空间是耦合的。
3. 因此"七种方法共用 S-C48"这件事**不是接线工作，而是要重写各自的求解器**：
   - SafeDiffuser：需要在控制点空间里保持可解、又不退化的 CBF（可行方向法/内点法，
     或"先算曲线速度再回投"的两级方案）；
   - Projected / PDM：需要接受"控制点空间的可行集可能是空集"这一事实，
     要么放松到整段约束、要么把状态从控制点换成曲线采样点；
   - PD / ALM：需要按 `J` 的尺度重新推导乘子与惩罚系数。

## 6. 建议（明确）

**不要把七种循环切到 S-C48 的控制点空间，也不要为此改基座。** 三条可选路线：

| 路线 | 内容 | 代价 | 风险 |
|---|---|---|---|
| **B1（推荐）** | 七种循环继续跑在**点表示**上（现状），S-C48 只用于"生成器质量"与"Ours"那条线；对比表分成"点表示七方法"与"B 样条生成器"两张 | 0 | 论文里必须说明两个基座不同 |
| B2 | 保留 S-C48，但给七种方法各写**曲线采样点状态**的适配（把 48 控制点当参数、优化 128 个曲线点再回投） | 每种方法 2–5 天 | 需重新论证与论文公式的一致性 |
| B3 | 只把 SafeDiffuser 三种接到 S-C48（它们跟随 DDIM 名义，不依赖投影），并把 CBF 换成可行方向法 | 3–5 天 | 仍是 16 级日程的 12.4 m 噪声下限 |

本阶段未做（按任务书）：未重训、未正式 test 集、未为了让表好看而调 `relax_weight`/`η`/`ρ`。
