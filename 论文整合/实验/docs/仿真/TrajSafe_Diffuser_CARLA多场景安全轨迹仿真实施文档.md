# TrajSafe-Diffuser：CARLA 多场景安全轨迹仿真实施文档

## 1. 实验目标

在 CARLA 的真实三维道路环境中布置多个**静态障碍场景**，调用现有加速版 TrajSafe-Diffuser 生成轨迹，并让自车实际跟踪轨迹驶向目标点。实验重点是展示安全轨迹生成、车身级避障和实际车辆执行效果，不研究跟车策略、变道决策或多车博弈。

**实施原则：** 复用现有 CARLA 接口、占据栅格构建流程、规划器推理接口和车辆控制器；不重写规划算法、不另建复杂交通系统、不重新制作地图。主要通过配置道路位置、起终点和静态障碍物完成场景搭建。

## 2. 总体流程与约束

整个流程应为：

`CARLA 三维场景 → 占据栅格/坐标变换 → TrajSafe-Diffuser（加速版）→ 安全检查 → 轨迹跟踪控制器 → CARLA 自车`

开始前先检查现有代码并复用已有接口。确认以下信息一致：CARLA 世界坐标、占据栅格坐标、规划器输入输出坐标、轨迹航向和车辆控制器使用的坐标。若轨迹整体偏移、旋转或左右镜像，应先修复坐标变换，不要通过修改规划结果来掩盖问题。

固定天气、光照、仿真步长和自车蓝图；关闭非必要的 Traffic Manager 车辆与行人。障碍物使用 CARLA 中实际可见的静止车辆、交通锥或施工隔离栏。自车起终点应沿道路设置，终点位于可行驶区域内。每个场景先检查是否存在合理通路，再调用规划器。

使用现有加速版模型和已验证的推理参数，不要在本实验中同时修改网络权重、损失函数或 ALM 算法。规划耗时以实际墙钟计时为准，不预先假设一定达到某个数值。

## 3. 场景设计

建议先实现 S1、S2、S3，再扩展至 S4、S5。所有场景均使用现有 CARLA 地图和道路。若地图中没有完全匹配的道路形态，选取最接近的现有路段并记录实际位置，不要为匹配示意图而重建地图。

### S1：车道内静止车辆绕行

**目的：** 验证基本障碍物避让和道路边界约束。

- 选择较直、视野开阔的城市道路。
- 在自车前方车道内放置一辆静止车辆，使其部分占据正常行驶区域，但保留合理绕行空间。
- 自车从障碍物前方驶向障碍物后方目标点。
- 轨迹应绕开静止车辆，同时保持在可行驶道路范围内。

检查轨迹是否与障碍车辆或道路边界冲突、自车能否实际绕过障碍，以及车辆执行时是否碰撞或明显偏离轨迹。

### S2：施工路段与狭窄通道

**目的：** 验证受限空间内的车身级安全可行性。

- 在较直道路上布置交通锥和/或施工隔离栏，形成有入口、狭窄区域和出口的通道。
- 自车从施工区前方驶入，穿过通道并驶向出口后的目标点。
- 通道宽度根据实际车辆宽度及现有安全膨胀参数设置，先保证可通行，不要一开始就把通道设得过窄。

重点检查车身扫掠范围是否位于通道内，以及“中心线无碰撞但车身擦碰”的情况能否被识别。如果安全约束过于保守而导致可通行场景无解，应记录并检查地图膨胀参数，不得静默关闭障碍物约束。

### S3：弯道附近的障碍物绕行

**目的：** 验证曲线路段中安全约束与轨迹几何形状的兼容性。

- 选择 CARLA 中一段可正常通行的弯道路段。
- 在弯道入口、弯道外侧或出口附近放置静止车辆或路障。
- 起点位于弯道前方，目标点位于弯道后方。
- 障碍物迫使轨迹在弯道中调整，但仍保留可行通路。

重点检查车辆前后角是否可能越出可行驶区域、曲线是否与障碍物冲突，以及自车能否稳定跟踪轨迹。

### S4：交错障碍物连续绕行

**目的：** 验证连续多个局部障碍下的轨迹生成能力。

- 在较直道路上沿行驶方向布置 2–3 个静止障碍物。
- 障碍物左右交错摆放，形成连续的 S 形通路，并保留足够车身通行宽度。
- 起点位于第一个障碍物之前，目标点位于最后一个障碍物之后。

重点检查轨迹能否连续绕过所有障碍物、车身扫掠范围是否保持安全距离，以及是否出现不必要的剧烈摆动或局部折返。

### S5：路口或分支道路中的局部阻塞

**目的：** 展示道路形态较复杂时的安全可行通路规划。

- 选择现有地图中有路口、岔路或多条连接道路的区域。
- 在其中一条可选通路上放置静止车辆或隔离栏，但至少保留一条从起点通向目标点的合理路线。
- 起终点设置在可行驶区域内，目标方向明确。

本场景不要求实现交通规则决策，只检验在当前占据地图和指定目标下能否生成安全轨迹。如果现有规划器不支持该路口的拓扑表达，应记录为接口或场景适配限制，不得手工修改最终轨迹伪造成功。

## 4. 场景配置与复现

每个场景应独立配置，不要将地图坐标硬编码到规划算法中。沿用项目现有配置格式；若没有现成格式，可建立简单的 YAML/JSON 配置，至少记录：

- 场景 ID、说明和 CARLA 地图名；
- 自车蓝图、起点、初始朝向和目标点；
- 障碍物蓝图、世界坐标、朝向和尺寸；
- 占据栅格及障碍物膨胀参数；
- 规划器配置名称和是否执行车辆跟踪；
- 规划耗时、碰撞结果、目标到达结果及日志路径。

占据栅格应反映实际静态障碍物，并正确处理不可行驶区域/道路边界。确认自车没有被错误地当作前方障碍物。不要在规划器之外手工删除会影响安全判断的障碍物。

每个场景运行前，在 CARLA 中同时绘制起点、目标点、障碍物边界、规划轨迹采样点，检查它们是否与实际道路位置对齐。所有坐标转换沿用现有接口的定义，不要另行引入第二套坐标约定。

## 5. 关键要求：车身级轨迹可视化

### 5.1 视觉目标

参考文件 `reference_vehicle_footprint.png`。最终画面应接近“真实 CARLA 道路 + 实际车辆模型 + 宽的半透明绿色轨迹带”，不能只画一条细中心线。至少展示：

1. 自车当前的真实车身；
2. 规划轨迹中心线；
3. 轨迹对应的车身宽度和扫掠范围；
4. 安全走廊或可行驶区域；
5. 静态障碍物及道路边界；
6. 起点、目标点和规划状态。

### 5.2 车身扫掠范围的实现

不能只对轨迹中心线做碰撞判断。应从自车蓝图或 CARLA BoundingBox 读取实际车身长度、宽度和局部偏移，并沿轨迹按航向放置一系列车身矩形。

- 车身尺寸优先读取车辆蓝图/BoundingBox，不要凭视觉估计。
- 每个采样姿态的朝向由轨迹局部切线或规划器输出的航向确定，并使用现有坐标变换。
- 沿轨迹按约 2–4 m 间隔绘制车身轮廓；急弯和障碍物附近加密。
- 将相邻车身轮廓连接，形成连续的车身扫掠区域。可视化带状区域必须反映车身长度和宽度，而不是只加粗中心线。
- 若现有渲染接口支持半透明多边形/网格，优先绘制半透明绿色带；若不支持，至少绘制左右边界、横向截面和采样车身轮廓，确保从 CARLA 视角能看出车辆实际占用范围。
- 真实自车继续使用 CARLA 车辆模型。不要沿整条轨迹生成大量不透明的重复车辆模型，以免画面杂乱。

### 5.3 推荐显示样式

- **最终轨迹：** 绿色中心线 + 半透明绿色车身扫掠带。
- **安全走廊：** 浅绿色或青绿色，与车身扫掠带区分。
- **未修正轨迹（仅调试时）：** 橙色虚线；正式录屏可关闭。
- **静态障碍物：** 保留 CARLA 中真实车辆、锥桶和隔离栏模型，并可叠加边界框。
- **车身轮廓：** 沿轨迹间隔绘制半透明矩形或线框，急弯处加密。
- **起点/目标点：** 使用不同标记并标注 Start/Goal。
- **状态信息：** 显示场景 ID、规划成功/失败、规划耗时、最小安全距离和碰撞状态。

颜色可沿用项目现有配色，但轨迹、障碍物、车身扫掠范围必须清晰可区分。

### 5.4 摄像机和画面布局

使用 CARLA 斜俯视跟随视角，保证同时看到自车、前方障碍物和大部分规划轨迹。摄像机高度根据场景范围调整，避免过近导致轨迹超出画面或过高导致车身细节不可见。轨迹带应与道路表面位置一致，不能悬空、埋入路面或发生明显横向偏移。

正式录屏时关闭无关调试线、重复标记和控制器中间变量。每个场景至少保存一张完整截图和一段从起点到终点的视频。

## 6. 规划、执行与安全检查流程

每个场景均按以下流程执行：

1. 加载指定 CARLA 地图，生成静态障碍物并设置自车起终点。
2. 检查道路、障碍物、起终点和占据栅格之间的坐标对齐。
3. 调用现有加速版 TrajSafe-Diffuser 生成轨迹。
4. 执行现有安全约束检查，并检查车身扫掠范围是否与障碍物或不可行驶区域重叠。
5. 仅当规划有效且安全检查通过时，才交给现有控制器执行；规划失败时不得直接执行失败轨迹。
6. 行驶过程中记录实际位置、规划轨迹、跟踪误差和 CARLA 碰撞传感器结果。
7. 到达目标点或发生失败后停止本次运行，保存日志、截图和视频。

若车辆跟踪出现较大偏差，先检查坐标变换、轨迹航向、控制器输入和车辆动力学，不要直接把跟踪误差归因于扩散规划器。

## 7. 评价指标与记录内容

本实验定位为 CARLA 场景应用验证，不要求额外搭建庞大的对比实验。每个场景至少记录：

| 指标 | 记录方式 |
|---|---|
| 规划是否成功 | 规划器是否输出有效轨迹 |
| 目标是否到达 | 自车是否在设定容差内到达目标区域 |
| 实际碰撞 | CARLA 碰撞传感器记录 |
| 最小障碍物间距 | 实际车辆与静态障碍物的最小距离，并注明计算方式 |
| 车身扫掠检查 | 规划轨迹对应的车身占用区域是否与障碍物/不可行驶区域重叠 |
| 实际跟踪误差 | 实际车辆位置与参考轨迹的横向或位置误差 |
| 单次规划耗时 | 规划器调用的实际墙钟时间 |
| 失败原因 | 无可行轨迹、ALM 失败、坐标映射错误、车辆跟踪失败等 |

必须区分规划轨迹的离散碰撞检查、车身扫掠检查和实际车辆碰撞传感器结果。三者用途不同，不能互相替代；不能仅凭中心线采样无碰撞就宣称实际车身绝对安全。

## 8. 实施顺序

### 阶段 1：单场景跑通

先实现 S1“车道内静止车辆绕行”，验证场景创建、占据栅格、规划调用、坐标变换、车身扫掠显示和实际跟踪的完整链路。

### 阶段 2：扩展场景

在不改动规划算法的前提下，增加 S2 施工窄通道和 S3 弯道障碍。两者稳定后，再增加 S4 交错障碍和 S5 路口阻塞。

### 阶段 3：完善可视化与记录

统一各场景的颜色、摄像机视角、状态面板、文件命名和日志格式。确保绿色轨迹带确实体现车身扫掠范围，而不是只画中心线。

### 阶段 4：批量运行与复核

依次运行全部场景，检查每个场景是否具有可复现配置、截图、视频和结果日志。失败案例也要保留并记录原因，不要只保留成功案例。

## 9. 验收标准

- [ ] 至少完成 S1、S2、S3；时间允许时完成全部五个场景。
- [ ] 场景在 CARLA 真实三维道路中运行，障碍物为实际 CARLA Actor。
- [ ] 自车调用现有 TrajSafe-Diffuser 生成轨迹，并由车辆控制器执行。
- [ ] 轨迹不是单独细线，能够体现车身长度、宽度及连续扫掠范围。
- [ ] 轨迹带、真实车身、障碍物和道路位置对齐，没有明显坐标偏移。
- [ ] 每个场景记录规划结果、碰撞结果、目标到达结果和规划耗时。
- [ ] 失败场景有日志和原因说明，规划失败的轨迹不会被强行执行。
- [ ] 不手工修改生成轨迹，不关闭必要的障碍物约束来制造成功结果。
- [ ] 提供场景配置、运行命令、截图、视频和简短 README。
