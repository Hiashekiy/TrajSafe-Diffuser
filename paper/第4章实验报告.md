## 摘要：三句话结论

1. **主表**：完整方法（A-C48 + 走廊 ALM + 历史反馈 + 末端投影）在 **3 个 seed × 420 条**上取得
   **0/1260 碰撞、100% SDF 可行、RMSE 10.47 m、平滑度 0.030 m**；四个 SDF 外部约束处理器把
   D-C48 下界的 67.46% 碰撞率降到 17.46%–65.79%（固定惩罚最好），但没有任何一个能压到 20% 以下。
2. **消融**：在 A-C48 先验上，**走廊 ALM 单独（无历史反馈、无末端投影）就足以把 10.71% 降到
   0/420**；历史反馈的价值体现在两处——引导阶段的工作量（原始违规 −32%、修正量 −37%、λ_max
   −30%）与**弱先验**情形（S-C48：30.24% → 0.24% → 0%）。因此"安全"主要来自先验 + ALM +
   投影三者叠加，而不是任何单独一项。
3. **效率**：走廊向量化让完整方法从带负载下的 371 ms/轨迹降到空载 **125.8 ms/轨迹**（主表 420 条）
   / **90.4 ms**（128 条同协议重测）；把相邻锚点合并共用一个凸区域（`region_stride=8`）在 4 步
   模式下再降到 **36.6 ms/轨迹（相对同批 stride=1 为 2.62×）**，而碰撞、可行率、RMSE、平滑度
   **一位未变**。

### 1.3 统一评价协议（指南 4.1.3 / 4.1.4）

- **碰撞判据（权威）**：解出的 128 控制点解码为 512 个稠密点，逐点做双线性占据插值，
  占据 > 0.5 或越出 `\|p\| ≤ 1`（裁剪边界）即判该轨迹碰撞。GT 参考：0 碰撞、RMSE 0.0008 m、
  平滑度 0.0218 m、最小安全距离 4.079 m。
- **SDF 量（辅助）**：占据栅格的 EDT 场 + 方向场，`d_safe = 0`；报最大残差、非负违规量、
  逐点平均违规、可行率、最小距离、安全点比例，并另列含裁剪边界的组合场违规量
  （`sdf_full_violation_m`）与离线/在线走廊的违规量与归属率。
- **逐样本记录**：每次运行同时落盘聚合 JSON、单次摘要 MD 与逐样本 JSONL（含碰撞、残差、
  可行、RMSE、平滑、耗时、`solver_status`、走廊是否引导）。
- **求解失败如实计入**：`solver_status` 逐次统计，失败时保留输入并标记，不做重试或伪造可行解。
- **计时**：按 chunk 计时、剔除预热 chunk、除以批大小；同时报**墙钟**（`time.perf_counter`，
  即调用方等待的延迟）与**进程 CPU 时间**（`time.process_time`）。§2.3/§3.1–§3.4 全部在
  **空载机器**（CPU 负载 6%）上重测。

### 1.4 公平性控制（指南 4.1.4 八条）

| 要求 | 落实 |
|---|---|
| 前五行共用同一 checkpoint | D-C48 的 `best_task.pt`，五行逐字节相同（sha1 `a39155a1c61b7fc7`） |
| 同 seed 下相同初始噪声与顺序 | 噪声由 `(seed, 全局样本下标)` 决定，因此**同一样本在所有方法里拿到完全相同的一份噪声**；chunk 划分一致 |
| 四个基线共享同一 SDF / 地图边界 / `d_safe` | 同一 `OccupancySDF` 实现、同一含边界组合场、`d_safe = 0` |
| 超参只在验证集选、选定后冻结 | `scripts/ch4_sweep_val.py` 在 val 的固定 256 样本子集上跑网格，选择规则事先写死：**碰撞数 → 平均违规量 → RMSE → 逐点平均违规**；完整网格落盘可查 |
| 测试集只用于最终评价 | 选参脚本只接受 `--split val` |
| 相同引导起始步与总体内迭代预算 | 预热同为 3 个已执行反向步；内迭代预算统一固定为 **10**（= 完整方法 `alm.inner_steps`），Projected 的顺序凸化次数同样计入这 10 次 |
| 统一 512 点碰撞与 SDF 残差 | 所有方法共用同一 `evaluate_controls` 实现 |
| 求解失败计入失败率 | `solver_status` 逐次统计 + 每样本失败计数（§2.4） |
| 计时协议 | 空载机器、预热后统计、同时报墙钟与进程 CPU（§2.3） |
| 开发期不变量检查 | 推理期关闭 `model.assert_shapes`（每次前向的 `isfinite().all()` 会强制 CUDA 同步，实测占 18%）；它不参与任何计算，`--keep-assert-shapes` 可恢复 |

**冻结的超参**（本批实验实际使用，即主表与 §3.3 的配置）：

| 处理器 | 冻结参数 | 网格点数 | 选择依据 |
|---|---|---:|---|
| Penalty | `penalty_weight=5, step_size=0.1, inner_steps=10` | 12 | val 碰撞 69/256 最小 |
| Projected | `inner_steps=10` | **1** | 见下方说明 |
| Primal-Dual | `step_size=0.05, dual_step=1, inner_steps=10` | 9 | val 碰撞 62/256 最小 |
| SDF-ALM | `rho=1, step_size=0.05, inner_steps=10` | 9 | val 碰撞 63/256 最小 |

两点如实说明：

1. **Projected 的网格退化为单点。** 指南 4.1.2 给它唯一的旋钮是顺序凸化次数 `{3,5,10}`，而
   4.1.4 第 6 条要求四个基线共享同一内迭代预算（10 = 完整方法的 `alm.inner_steps`）。固定预算
   后该网格只剩 `inner_steps=10` 一个候选，**等于没有做搜索**。这是已披露的公平性决策的后果，
   不是遗漏，但它确实意味着 Projected 只在预算上限上被评估过。
2. **Penalty 网格存在冗余维度。** `(penalty_weight=5, step_size=0.1)` 与
   `(10, 0.05)` 的 256 条聚合指标**逐位相同**（碰撞 69、平均违规 3.1741724599560257、
   RMSE 18.393513480201364、平滑度 0.17786363754566992）——有效旋钮是二者的乘积。并列时
   "胜者"由网格枚举顺序决定，选择规则的字典序无法区分它们。

### 2.2 安全性与轨迹质量分析（指南 4.2.2 的六问）

1. **标准 Diffusion 是否存在明显碰撞与违反**：是，且非常严重。67.46% 的轨迹碰撞，SDF 平均
   违规 7.634 m、P95 25.412 m、最大 38.438 m；只有 33.17% 的轨迹满足 `V ≤ 1e-3`。平均每条
   轨迹有 34.5% 的点落在预处理障碍内（安全点比例 65.51%）。
2. **固定惩罚是否降低平均违反但仍难稳定可行**：是。它把碰撞率降到 17.46%（850 → 220），可行率
   33.17% → 87.06%，平均违规 7.634 → 2.233 m，是所有基线里**安全点比例最高（99.47%）与最小
   安全距离最好（−1.145 m）**的。但 P95 违规仍有 20.919 m，说明长尾里仍有深度侵入的样本；且
   平滑度从 0.027 恶化到 0.154 m（**5.6 倍**），这是逐点推开障碍点、缺少沿控制轴的耦合所导致的
   折角。
3. **局部线性化 SDF 逐步投影是否提高可行率、是否增加 RMSE 或不平滑**：可行率确实提高
   （33.17% → 56.27%），平均违规降到 2.720 m，但**碰撞率几乎没降（67.46% → 65.79%）**；P95
   违规量 22.174 m 与 Diffusion 同量级。原因见 §2.4：**14.33% 的投影求解失败**，失败时按指南
   保留原始预测。平滑度恶化到 0.120 m（4.4 倍）。
4. **Primal-Dual 相较固定惩罚是否更稳定**：**否**。碰撞率 20.56% 高于固定惩罚的 17.46%，可行率
   79.76% 低于 87.06%，平均违规 3.776 m 也更大；P95（24.051 m）接近 Diffusion（25.412 m），
   说明尾部几乎没有被压制。它相对固定惩罚的唯一优势是平滑度（0.107 vs 0.154 m）。
5. **SDF-ALM 相较 Primal-Dual 是否进一步降低平均与尾部违规**：是，但幅度有限。平均违规
   3.776 → 3.645 m，P95 24.051 → 23.394 m，碰撞率 20.56% → 19.05%，可行率 79.76% → 81.03%，
   平滑度 0.107 → 0.090 m。二次惩罚项的改善**一致但温和**。
6. **生成式连续走廊的完整方法是否在可接受的 RMSE 与平滑度代价下取得更低碰撞率**：是，且代价
   方向与预期相反——它同时取得**更低碰撞率（0.00%）**、**更低 RMSE（10.47 m，比所有 SDF 基线
   低约 3.7 m）**与**更好的平滑度（0.0297 m，约为基线的 1/4）**。代价只有时间：125.8 ms/轨迹，
   是 Diffusion 的 3.1 倍、SDF 基线的 2.1 倍（空载重测；旧版带负载数字为 371.2 ms，已作废）。

   **必须单独声明**：这一行使用 **A-C48**，前五行使用 **D-C48**，两者的无处理碰撞率相差
   10.71% vs 67.46%（§1.2）。因此它的 RMSE 优势里既有约束处理的贡献，也有模型本身更强的贡献。
   主表属于**端到端系统比较**。

### 2.3 推理时间（指南 4.2.3）

主表的 `时间` 列是空载机器（负载 6%）上、同一协议（16 步、chunk 32、剔除预热 chunk）下
对**前 128 条测试样本**重测的结果：

| 方法 | 墙钟 ms/轨迹 | 进程 CPU ms/轨迹 | 网络前向 | 约束优化 | 末端投影 |
|---|---:|---:|---:|---:|---:|
| Diffusion | 31.5 | 29.3 | 29.9 | — | — |
| Penalty-guided | 42.0 | 40.2 | 29.8 | — | — |
| Projected | 743.3 | 717.5 | 30.8 | — | — |
| Primal-Dual | 42.4 | 39.6 | 29.8 | — | — |
| SDF-ALM | 44.1 | 40.3 | 29.7 | — | — |
| 本文完整方法 | 90.4 | 133.2 | 31.5 | 5.1（走廊 ALM） | 10.4（LP 10/128） |

**计时口径**：同时报**墙钟**（调用方实际等待的延迟）与**进程 CPU 时间**（不受其他进程争抢
影响）。完整方法的 CPU 时间高于墙钟，是因为计时区间里含跨线程/内核的求解工作，CPU 时间会
跨线程累加，所以 **CPU 时间不能当延迟指标**；它只用来判断测量是否被外部负载污染。分项计时
只在区间边界做 CUDA 同步，相邻区间会互相渗入，**以墙钟为准**。

**读法**：① 除 Projected 外，五个方法的网络前向都在 29.7–31.5 ms，即**推理耗时几乎全部是
一次前向**；② Projected 是唯一的例外（743.3 ms，约 24 倍），因为它每个引导步都要解一批 QP；
③ 完整方法 90.4 ms = 31.5（网络）+ 5.1（走廊 ALM 13 步）+ 10.4（末端投影，128 条里只有 10
条真正求解 LP）+ 其余。

> 跨表比较注意：上表是 128 条样本的子集，主表 `时间` 列（§2.1）是全部 420 条、含 Town02/10HD
> 等更密集的场景，因此同一方法两处可差 10–20%（完整方法 90.4 → 125.8 ms）。**同一次测量
> 内部的比值才是结论，跨表的绝对值只作参考。**

### 2.4 求解失败率（指南要求单列，不隐藏）

每个方法共 420 × 13 × 3 = **16380** 次约束处理尝试：

| 方法 | OK | 求解失败 | 回滚（改差则保留输入） | 受影响轨迹（每 seed） |
|---|---:|---:|---:|---:|
| Penalty-guided | 16376 | 0 | 4（0.02%） | 3 / 0 / 0 |
| Projected | 14033 | **2347（14.33%）** | 0 | **116 / 118 / 117（27.9%）** |
| Primal-Dual | 15177 | 0 | 1203（7.34%） | 81 / 79 / 73 |
| SDF-ALM | 15316 | 0 | 1064（6.50%） | 72 / 74 / 64 |

Projected 的失败构成：1528 次"原始不可行（primal infeasible）"、585 次"达到最大迭代"、234 次
"原始不可行（不精确）"。**失败时保留 `Q0_raw` 并记录 `projection_failed`**（指南 4.1.2 §3 的
明确要求），不做任何伪造可行结果。这正是它碰撞率降不下来的直接原因：**非凸占据栅格 SDF 的
局部线性化半空间彼此冲突**，而本文的走廊 ALM 作用在**凸**走廊上，可行性由构造保证。

Primal-Dual / SDF-ALM 的"回滚"是单调守卫（结果变差则保留输入）触发的，属于"该步没有改进"，
与 Projected 的求解失败性质不同，表中分开列出以免混淆。

### 2.5 越界（裁剪边界）诊断

评价协议把越出 `[-1,1]²` 计为碰撞，而指南定义的 `r^SDF` 只描述占据栅格、不含裁剪边界，两者
在边界附近可以同时成立。各方法越界轨迹比例：Diffusion 3.33%、Penalty 0.40%、Projected
0.63%、Primal-Dual 2.14%、SDF-ALM 1.35%、**完整方法 0.00%**。四个 SDF 基线使用的是**含边界的
组合场**，越界在其约束里可见；主表另设 `sdf_full_violation_m` 一列记录该组合场的违规量，避免
读者误判"可行率 100% 却有碰撞"。

## 3. 推理效率：计时、向量化与两种降本手段

> 本节全部测量都在空载机器（CPU 负载 6%）上完成。**绝对延迟在不同测量轮次之间有 10–20% 的
> 漂移**（同一台机器的 GPU/CPU 热状态不同），因此本节的结论只用**同一次测量内部的比值**。

### 3.1 成本结构（4 步模式下，逐 chunk 交替测量，420 条）

| 阶段 | 4 步 ms/轨迹 | 16 步 ms/轨迹 | 随步数变化 |
|---|---:|---:|---|
| 网络前向 | 8.1 | 32.1 | 是（∝ 步数） |
| 走廊 ALM（每步一次） | 0.8 | 7.1 | 是（∝ 引导步数） |
| 末端投影 | 35.3 | 22.4 | 否（但样本相关） |
| **其余** | **44.5** | **43.7** | **否** |

"其余"是**与步数完全无关**的固定成本，含走廊构建 + 约束包构造 + DDIM 记账 + 解码 + 候选处理。
§3.4 用凸区域共享把它进一步分解为 `≈ 14 ms（固定）+ 0.26 ms/细胞`。

### 3.2 走廊构造的向量化（7.4×）

走廊构建原先每个细胞调用 2 次 Qhull（`HalfspaceIntersection` + `ConvexHull`），每次各创建一个
临时文件——1024 个细胞就是 2048 次 `mkstemp`，实测 `mkstemp` 3.4 s + `nt.open` 2.8 s。改动：

| 改动 | 内容 |
|---|---|
| 顶点改闭式解 | 二维凸多边形的每个顶点都是两个面的交点，"枚举面配对 + 按角度排序"即精确解，不再需要 Qhull |
| 重叠面积改半空间 | `area(A∩B)` 用两组半空间直接求顶点，无需 Python 版 Sutherland–Hodgman 裁剪，且每细胞面积只算一次 |
| 去掉 `np.roll` | 鞋带公式改用切片 |
| 搬运提出循环 | 每细胞的 device→host 拷贝从 2 次降到 0 次（批量转换） |
| 推理期关闭 `assert_shapes` | 每次前向的 `isfinite().all()` 强制设备同步，占 2.8 s 运行的 18% |

**实测（32 条测试轨迹、完整方法、16 步、预热 + best-of-3、同一测法）**：`616 → 88.3 →
83.1 ms/轨迹`（616 / 83.1 = **7.4×**）；本轮空载重测为 **77.2 ms/轨迹**；走廊 32/32 仍然有效、
0 碰撞。

**等价性**：`tests/test_corridor_speedup.py` 用**保留的 Qhull 原实现**
（`_vertices_qhull_reference`）在 >80 个真实细胞上断言顶点集、循环顺序、面积（1e-12 相对）
与重叠率一致，并覆盖退化输入（空/无界/重复面/零范数法向）。几何本身未变，因此 §2、§4、§5
的表格数字仍然成立。

**负结果（一并记录以免重复尝试）**

- **末端投影的 LP 线程池：负收益且不安全，已撤回。** 微基准上 32 个 LP 由 1.296 s 降到 0.261 s，
  但在**完整 420 条测试集上会把进程永久锁死**：一个 chunk 内并发 14 个 `scipy`/HiGHS LP，其中
  某次求解在原生代码里长时间持有 GIL（py-spy 实测：单核 100% 空转、12 s 采样到 **0 个 Python
  帧**），主线程卡死在 `ThreadPoolExecutor` 的 `Thread.start()` 上；而 `linprog` 既没有 `maxiter`
  也没有超时，因此**永不返回**（实测卡死在第 9 个 chunk，256/420，8 分钟无任何进展）。
  现在 `alm.projection_workers` 显式钉为 **1（串行）**。
- **多边形批量提取：零收益，已从主路径移除。**
  `vertices_pairwise_batch`（`src/geometry/convex_region.py`）把 128 个细胞按最大面数 padding 成
  一次向量化计算，端到端（16 步、32 条、同进程背靠背 A/B）：逐 cell 调用 **77.2** vs 批量
  **81.2** ms/轨迹 → **0.95×（没有加速；差异已接近噪声量级）**。原因是其成本为 `O(N·M³)`
  （`M` = 该批最大面数），细胞面数不均时反而更贵，且存在密集场景下时间/内存爆掉的风险。
  **走廊构建已改回逐细胞调用**；该 API 与其 3 个回归测试作为参考实现与负结果证据保留
  （两条路径在 3 个真实样本 × 128 个细胞上产出的顶点、面积、相邻重叠率逐位相同，max|ΔArea| = 0）。
- **OSQP 求解器复用**（`update(Ax=)`）：`P` 与 `A` 的模式虽固定，但数值一变就要重新分解 KKT，
  微基准仅 1.27×，端到端反而慢 41%（陈旧热启动抬高难样本的 ADMM 迭代数）。
- **OSQP 多线程并行无收益**：其 Python 封装持有 GIL（8 线程 7.28 ms vs 单线程 7.84 ms）。
- **关闭 `polishing` 属劣化**：会迫使 ADMM 在 eps=1e-7 下多迭代。

### 3.3 4 步去噪消融（完整 420 条测试轨迹）

项目既有的 4 步模式（`pick_times(16, 4)`，也是仪表盘默认值）：

| 步数 | 末端投影 | 墙钟 ms/轨迹 | 网络 | 走廊ALM | 末端投影 | 其余 | 碰撞 | SDF可行率 | RMSE | 平滑度 |
|---:|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 16 | 关 | 83.0 | 32.1 | 7.1 | 0.0 | 43.7 | 0/420 | 100.00% | 10.48 | 0.030 |
| 16 | 开 | 104.3 | 32.2 | 7.2 | 22.4 | 42.5 | 0/420 | 100.00% | 10.48 | 0.030 |
| **4** | 关 | **53.4** | 8.1 | 0.8 | 0.0 | 44.5 | **0/420** | **100.00%** | **10.06** | 0.038 |
| 4 | 开 | **87.2** | 8.2 | 0.8 | 35.3 | 42.9 | **0/420** | **100.00%** | **10.06** | 0.038 |

**结论**

1. **4 步比 16 步省 1.56×（83.0 → 53.4，关投影）与 1.20×（104.3 → 87.2，开投影），不是 4×**：
   步数只控制**网络 + 逐步 ALM**（16 步 39.2 ms → 4 步 8.9 ms）。
2. **步数无关的"其余"占大头**（43–45 ms/轨迹），继续减步数不能把它降下来——真正的杠杆是
   §3.4 的区域共享。
3. **安全性没有退化**：四格全部 0/420 碰撞、100% SDF 可行；4 步的 RMSE 反而略好（10.06 vs
   10.48），平滑度略差（0.038 vs 0.030）。
4. **协议上有一个必须说明的相互作用**：预热是**固定的 3 个反向步**（指南 4.1.4），所以 4 步
   模式下只剩 **1 个引导步**（16 步时是 13 个）。这直接反映在走廊 ALM 的耗时上（7.1 → 0.8 ms，
   即修正机会从 13 次降到 1 次）。在该模型 + 该协议下最终指标没有退化，但这意味着安全性主要
   来自模型本身与末端投影，**而非逐步 ALM**；换成更难的场景或更弱的先验时该结论不一定成立。
5. 指南 4.1.1 把「DDIM 采样步数」固定为 **16**。主表继续使用 16 步；4 步只作为**效率分析**。

### 3.4 凸区域共享（`region_stride`）：相邻锚点共用一个凸区域

128 个预测椭圆默认各自生成一个凸区域（128 个细胞）。把**每 k 个锚点合并成一个细胞**（末锚点
永远单独保留，保证终点区域不被共享），在 4 步模式下、完整 420 条测试轨迹上测量；四个配置
**逐 chunk 交替**执行，共享同一批样本与同一次机器状态：

| stride k | 细胞数 | 墙钟 ms/轨迹 | 加速比 | 网络 | 走廊ALM | 末端投影 | 其余 | 桥 | 碰撞 | SDF可行率 | RMSE | 平滑度 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 128 | 96.0 | 1.00× | 8.2 | 1.5 | 38.5 | 47.8 | 0 | 0/420 | 100.00% | 10.06 | 0.038 |
| 2 | 65 | 63.1 | 1.52× | 8.3 | 0.7 | 24.8 | 29.3 | 0 | 0/420 | 100.00% | 10.06 | 0.038 |
| 4 | 33 | 44.2 | 2.17× | 8.2 | 0.6 | 14.3 | 21.1 | 0 | 0/420 | 100.00% | 10.06 | 0.038 |
| 8 | 17 | 36.6 | **2.62×** | 8.0 | 0.8 | 9.8 | 18.0 | 0 | 0/420 | 100.00% | 10.05 | 0.039 |

**读数**

1. **共享打中的是当前最大的真实开销。** "其余"对细胞数近似线性：`≈ 14 ms（固定）+ 0.26 ms/细胞`
   —— 128 细胞约 33 ms，17 细胞约 4 ms。走廊 ALM 只有 0.6–1.5 ms、网络 8 ms，都不是瓶颈。
2. **末端投影同时变便宜**（38.5 → 9.8 ms）：LP 的不等式行数正比于细胞数。这一项与走廊构建
   无关，是共享的额外红利，也是 2.62× 里不可忽略的一部分。
3. **安全指标一位没动**：四档全部 0/420 碰撞、100% 可行、RMSE 10.06/10.05、平滑度 0.038/0.039。
   且 `bridges = 0`、`fails = 0`：步长变宽**没有**让相邻区域的重叠率跌破阈值，因此没有触发任何
   按需补桥——原本担心的"补桥成本抵消共享收益"没有发生。
4. **这组数字只在 4 步模式下成立，不能外推到 16 步。** 4 步只剩 1 个引导步，走廊 ALM 只占
   0.8 ms，安全性主要来自模型本身与末端投影；16 步时走廊要在 13 个引导步里持续起作用
   （ALM 7.1 ms），"粗走廊能否守住"必须单独验证。**因此主表不采用任何 stride > 1 的配置，
   16 步下的共享实验列为待办。**

`region_stride` 默认值为 1（等于原始行为），并由 `tests/test_corridor_speedup.py` 钉住：默认/1/0
三条路径产出的走廊完全一致；在 12 锚点上 stride = 2/4/8 分别得到 7/4/3 个基础细胞，且**末锚点
始终独占一个细胞**。

   **引导阶段原始违规 3.351 → 0.627 m（降 81%）、修正量 3.555 → 0.709 m（降 80%）、
   λ_max 0.211 → 0.043（降 80%）、逐步可行率 0.630 → 0.942**。即**训练期反馈把 ALM 需要做的
   活减少了约 5 倍**，并让弱先验下的最后一条残余碰撞消失。代价是 RMSE 略高（9.78 → 10.48 m）、
   平滑度更好（0.046 → 0.030 m）。
3. **协同方向明确**：有训练期反馈时，ALM 的 λ 与内迭代都显著更低（λ 0.043 vs 0.211，内迭代
   约 6 vs 8–10），说明反馈训练让约束在生成时就更容易被满足，ALM 只需做小幅修正。
4. **预算声明**：S-C48 用 100 epoch、A-C48 用 200 epoch，两者都取 ≤100 的有效 horizon 内、按
   同一 task 准则选出的 epoch（65 与 55）。因此本表是"同准则、同有效 horizon"的对照，
   **不声称严格训练阶段消融**。

### 6.1 逐步过程读出的结论

1. **预热与引导的分界清晰**：所有带处理器的运行在第 1–3 个已执行反向步的 `active_n` 都是 0，
   第 4 步起跳到 420 并在其后保持 420，与指南"前 3 步 warmup"的要求一致；四个 SDF 基线与走廊
   方法**共用同一个预热长度**。`guidance=none` 的运行（Diffusion、A0、T0、T2）全程 `active_n=0`，
   符合"不做任何安全处理"的定义。
2. **修正量随去噪推进而下降**：Penalty 的平均修正距离从第 4 步的 17.53 m 降到第 16 步的
   12.81 m，其修正前违规量同步从 8.133 m 降到 6.015 m；完整方法全程在 1.359 → 0.709 m 的
   亚米级。说明**在扩散早期就把干净预测拉回可行域**是有效策略，而不是把问题留给末端。
3. **修正的"有效率"把处理器分成两类**：Penalty 与完整方法的修正效果随步数**变好**
   （Penalty：违规量被压低的幅度 72% → 76%；完整方法 94% → 97%），而 Primal-Dual 与 SDF-ALM
   **变差**（67% → 39%、67% → 40%）——它们的修正后违规量在第 16 步反而高于第 4 步
   （2.724 → 3.912 m、2.648 → 3.848 m），与其 7.34% / 6.50% 的回滚率一致：后段修正经常被
   单调守卫判为"变差"而作废。
4. **逐步可行率与求解失败率一致**：Projected 的逐步可行率（0.826–0.868）并不比 Penalty 差，
   但它的**求解失败率 14.33%** 意味着这些"可行"里有一部分是靠保留原始预测得到的，这与它
   最终 65.79% 的碰撞率直接对应（§2.4）。
5. **约束激活成功率 100%**：所有 `guidance=alm` 的运行都是 420/420 条轨迹成功建立并冻结走廊，
   没有样本落入 `activation_failed`。

## 9. 局限性与如实声明

1. **主表最后一行不是同先验对照**（§2.2 第 6 点）：完整方法用 A-C48（无处理时 10.71% 碰撞），
   前五行用 D-C48（无处理时 67.46%）。"同一物理安全要求下的处理方式比较"只在**前五行之间**成立。
2. **训练预算不一致**（§5）：S-C48 100 epoch vs A-C48 200 epoch。T 表按"同准则、同有效 horizon"
   表述，不声称严格训练阶段消融。
3. **SDF 是平滑代理，不是碰撞判据本身**：主表碰撞率按 512 点双线性占据与 `\|p\|≤1` 判定，是权威
   指标；`r^SDF` 是指南定义的辅助量。边界附近两者可以不一致（§2.5）。SDF 由占据栅格的 EDT 构建
   后双线性插值，在障碍内部深处与真实欧氏距离存在插值误差。
4. **Projected 的高失败率是方法性质也是实现选择**：我们把"线性化后不可行"如实计为失败并保留
   原始预测（指南要求），没有用重试、松弛或多次重启去掩盖它。若允许更大的迭代预算或阻尼策略，
   其数字会改善，但那就不是指南定义的"固定最大迭代次数的逐步 L2 投影"了。
5. **选参网格的两个如实说明**（§1.4）：Penalty 的胜者 `step_size=0.1` 顶在网格上界；且
   `(5, 0.1)` 与 `(10, 0.05)` 的验证指标逐位相同（有效旋钮是乘积），并列时胜者由枚举顺序决定。
   Projected 的唯一旋钮即内迭代次数，固定为 10 后网格退化为单点，**等于没有搜索**。
6. **分项计时受 CUDA 异步影响**：只有区间边界做了同步，量级可信、精确归因以墙钟为准。
7. **效率数字只支持"同一次测量内部的比值"**：同一协议在不同轮次之间绝对延迟有 10–20% 的漂移
   （完整方法 16 步 + 投影：主表 420 条 125.8 ms vs 效率套件 104.3 ms）。主表 `时间` 列与 §2.3
   的 128 条重测也不可直接相减（样本子集不同）。**论文只应引用同一次测量内部的比较与加速比。**
8. **§3.4 的区域共享只在 4 步模式下验证**，主表不采用 stride > 1；16 步下的验证列为待办。
9. **已撤回的结论**（保留记录以免重复尝试）：① "走廊构建占完整方法运行时间 92%"来自 cProfile，
   该 profiler 会把 Python 调用密集的路径相对 CUDA 调用严重放大，不可引用；② 末端投影的 LP
   线程池在完整测试集上会锁死进程，其 1.60× 不成立；③ 多边形批量提取实测 0.95×，零收益，
   已从走廊构建的主路径移除（函数与测试保留作参考）。
10. **表格中的"可行""违规"一律相对预处理占据栅格与学习/生成的约束集**，不能直接推广为真实
    车辆道路安全率。
11. **未做的事**：k4p 与 k8p 的对比实验（指南明确不再设置）；每方法多组超参的测试集敏感性
    分析；4.3.2 的 200-epoch 同预算重训；16 步模式下的区域共享验证。
